# Harness · 配方工具白名单契约

规格事实源。对应实现: `src/harness/recipes.py` (`filter_schemas`)
与 `src/harness/routing.py` (`route_for_request`)。

## 背景

配方 YAML 里写 `tools: [...]` 白名单, 目的是把「这类问题该看哪几眼」固化下来,
可审计、可回归 —— 而不是让模型在 66 个工具里自由选。

## 验收标准

- **RECIPE-010** 白名单一个工具都没命中时必须**收紧到 0 工具**(fail-closed),
  不能回退到全量 —— 白名单写错就把 66 个工具全交给模型, 与白名单机制的目的正好相反
- **RECIPE-011** 白名单为 None / 空集时**不过滤**(返回全量) —— 这是显式的「不用配方」路径,
  与「白名单写错」是两件事, 不能混淆
- **RECIPE-012** 白名单一个都没命中时必须记 warning 并列出没对上的工具名 —— 排障时要能看出是哪份配方坏了

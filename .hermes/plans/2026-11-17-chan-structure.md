# 缠论结构图层开发计划

**目标**：在数智分析 Pro 的 K 线上提供可追溯、区分已确认/未确认的结构观察，供人和 AI 使用；不自动交易、不把结构称为收益保证。

**基线**：origin/main `2d1180c0`；独立 worktree `feat/chan-structure-1117`，不触碰正在开发的 `feat/theme-evolution` 工作区。现有 K 线 API `src/web/api/klines.py`、图表 `frontend/packages/biz-ui/src/components/KlineChart.tsx`，普通形态识别 `src/core/kline_pattern.py` 不等于缠论。

**口径**：先研究并固定一种有版本的规则；明确包含处理、等高低、分型、成笔距离与中枢定义，版本间不可混称。每个结构记录发生点和最早确认点；末根盘中 K 线、未确认结构独立标注。缺行情/缺复权/级别不支持返回 unknown，不推断停牌或成交。严格区分数学结构与投资结论。

## 阶段与依赖

1. **规则及黄金样例（本人负责）**：核对可追溯原始文献，固定 v1 规则、反例和重绘定义；建立顶底分型的纯函数，明确原始与处理后索引/确认时点。验收：包含、等高低、短序列、无效 OHLC 和增量截断样例；不把简化局部极值称完整缠论。
2. **笔与中枢（依赖 1）**：实现规则版本化、候选/确认状态、来源及截断一致性测试；先对用户指定和公开历史样例人工对照；定义无法判定边界。暂不实现背驰及一二三买卖点。
3. **数据接入（依赖 2）**：复用 K 线 API 的来源、周期和证券类型；日/周/月/分钟逐项按真实数据能力验证，不跨源拼接；只读端点强制认证并保留 source/as_of/adjustment/数据缺口。避免指数/股票同码混淆、行情缓存跨帐号与错误降级。
4. **图表图层（依赖 3）**：在现有 KlineChart 上可开关显示分型、笔、中枢；虚线/文字区分待确认，不遮挡 K 线；详情展示规则版本、发生与确认时间。空值、切标的、切周期、错误态及权限均测试；Lightweight Charts v5 真实组件 + 桌面/手机视觉验收。
5. **数智参谋与价值验证（依赖 4）**：AI 只引用同一份结构数据，不自行生成买卖点；截断一致性、时点冻结、复权和交易可得性验证；按同池同日对照、样本外和成本报告，不承诺 alpha。
6. **发版（依赖 1–4 验收）**：最终集成代码跑后端和前端门禁，GitHub CI、镜像构建及源码/镜像摘要核对；生产备份/回退、部署后真实数据及浏览器截图验收。禁止未经验收发布。与题材演化分支隔离，合并前检查 main 和并发工作。

## 第一施工切片

- 新建 `src/core/chan_structure.py` 与 `tests/test_chan_structure.py`：先写失败测试，再实现独立纯计算，行情输入必须有限、时序递增、OHLC 合法；先实现**严格三根原始 K 局部极值的实验性原语**，不声称已完成缠论分型或允许用于交易。
- 原语仅作实验基座：显式识别位置与确认位置，数据不作复权/包含变换，平顶平底标未判定；截断序列重算时已确认结果稳定。
- 验收命令：使用目标仓库 venv，清除所有继承的生产数据库连接及数据路径环境变量、TMPDIR 指向 scratch，运行 `pytest tests/test_chan_structure.py -q`（不得管道掩盖退出码）；运行 ruff、Python 编译检查。前端无修改时不声称页面已接。

## 明确不做

首切不做回测收益承诺、自动交易、无依据的中枢/背驰/买卖点、不接生产调度、不擅自更改题材工作或生产数据库；真实行情、浏览器验收及图层尚需后续阶段。

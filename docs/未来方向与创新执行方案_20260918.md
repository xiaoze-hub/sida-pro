## 一、现状一页纸（判断依据）

**强**：六图层 K 线 + §10.2 交互、数智决策三指标（活跃度/GS/L2 主力净流入）、集合竞价池、
AI 工具 28 个 + 外部 Skill 22 个、10+ 通知渠道、四档权限 + 可调免费档、CI 四线全绿 + 一条命令回滚的部署链。
**弱**（本轮实测）：
1. **口径三源并存但未产品化**——明盘 L2/暗盘逐笔/东财四档数字天然不同，刚做了对照页，但"差异"还只是页面，没变成**可追溯的信任资产**。
2. **决策链只到"看"没到"验"**——共振/信号能看，但"看了之后呢"缺闭环：没有决策日志 → 没有命中率归因 → 无法证明/证伪。
3. **UI 均分 6.3/10**——遮挡（9 页）、空态占巨幅空白（5 页）、theme-mood 4/10、heatmap 5/10；一致性（卡片 vs hairline）未收口。
4. **能力孤岛**——`forecast_lib`(8010 未跑)、`.img/.tck` 引擎无消费方、TradingAgents 与主决策链未打通。
5. **商业化只有骨架**——API Key/档位/免费档都在，但没有计量→计费→账单的闭环。

## 二、五个方向（按"护城河 × 可落地"排序）

### 方向 A：口径可信度 → 把"数字为什么不同"做成产品（护城河 #1）

- **依据**：全仓已有口径红线（AGENTS.md）、`data_quality_sentinel`、刚上线的 `/caliber-compare`。
  A 股数据服务同质化严重，**"每个数字都能说清出处与差异"** 是唯一难被抄的差异点。
- **做什么**：
  1. 口径对照**时序化**：把每天的对照结果落库 → 出"口径漂移曲线"（哪家源在什么行情下偏离多少）。
  2. **可溯源**：界面上每个关键数字可点开 → 数据源 / 口径 / 基准日 / 取数时间 / 质量标记（可疑时红标）。
  3. **质量哨兵产品化**：把 `data_quality_sentinel` 的告警从日志搬到通知中心 + 首页角标（"今天有 2 个源可疑"）。
- **指标**：被标记可疑的数据在下游页面占比、口径对照页周活、因数据误用导致的返工数（目标 0）。
- **风险**：口径说明文案要与业务同事对齐（避免"解释得太复杂"），用一页图示代替长文。

### 方向 B：决策闭环 → 从"看图"到"可验证"（护城河 #2）

- **依据**：有 GS/共振/竞价/纸交易/影子账户，但没有"决策 → 结果"的归因表；
  历史上 LLM 方向预测 31.7% < 抛硬币 50%，说明**必须靠可验证的信号而不是叙述**。
- **做什么**：
  1. **决策日志**：任何一次"共振判定/GS 信号/竞价池上榜"自动记一条（时间、标的、信号、当时证据快照、当时价格）。
  2. **命中率归因**：T+1/T+3/T+5 自动回填结果 → 分信号、分市场状态（情绪周期阶段）出命中率表。
  3. **策略迭代闭环**：把命中率低的信号自动降权/下架，高的加权重——用数据而不是感觉调信号。
  4. 与 `paper-trading` 打通：纸交易用"当前生效权重"跑，形成 A/B。
- **指标**：每个信号的样本量与命中率公开可见；纸交易相对基准的净值曲线。
- **风险**：样本量小时容易过拟合 → 强制最小样本（如 n≥30）才展示命中率，否则显示"样本不足"。

### 方向 C：Agent/API 经济 → 把 22 个 skill 变成可组合的能力市场

- **依据**：Skill Gateway + API Key + 四档 + 免费档（本轮做完）+ `docs/开发文档`，但缺计量/计费/账单。
- **做什么**：
  1. **用量计量**：按 skill/按用户/按天记录调用与耗时（部分已有 `high_value_api_logs`）。
  2. **计费与账单**：tier 定价表 → 月度账单页（owner 可改价，复用免费档那套 KV + 30s 热生效）。
  3. **组合编排**：把"选股 → 归因 → 复盘"做成可保存的 **Agent 工作流**（用户拼技能链，一键跑）。
  4. **对外可见的能力目录**：`/developers` 已有目录，补"每个 skill 的口径/延迟/计费/示例"。
- **指标**：外部调用量、付费转化、单个 skill 的复购。

### 方向 D：体验与终端感（本轮已启动）

- **依据**：UI 走查 6.3/10（遮挡 9 页 / 空态 5 页 / theme-mood 4 分）。
- **做什么**：B1 遮挡系统性修复（本轮已落码）、B2 空态压缩、B3 theme-mood/heatmap 信息设计、B4 一致性扫荡；
  之后做 **多分辨率回归**（1440/1600/1920 + 移动端）+ **暗/亮双主题**截图基线。
- **指标**：视觉均分 ≥7.5；遮挡类问题 0；空态页占比下降。

### 方向 E：数据资产化（把"跑了两年的数据"变成能力）

- **依据**：PG 里已有 K 线 hypertable（800 天）+ 龙虎榜/涨停/情绪周期/竞价快照等时间序列，但**没做特征/因子库**。
- **做什么**：① 统一特征口径落库（因子表 + 版本）；② 与既有 KD 指标做 IC 检验（已有 `factor_ic_report` 工具）；
  ③ 对外提供"因子 API"（与方向 C 合流）。
- **指标**：因子数、IC 稳定性、被策略引用的因子数。

**方法论（本轮立下）**：UI 问题**先量再改**——"看着有点挤/有点空"不算结论。
theme-mood 的 `16456px / 18 屏` 就是 DOM 探针量出来的（`/tmp/theme_mood_probe.py`），
空态 560px、图表 CDN 被 CSP 拦、份额<0.8% 的块标签碎片同理。凡能测的都测，测不了的说清测不了。

**执行机制（自主循环）**：
1. 每批开工前先跑一次 **可复现基线**：`python3 /tmp/ui_sweep.py` + `/tmp/ui_vision.py`（截图与视觉分），存 `/tmp/ui_review/before_<批次>/`。
2. 改动 → 门禁（后端 pytest / 前端四件套 / ui-rules / deploy stub）→ 复跑走查 → **分数环比上升**才算完成。
3. 完成后 `merge --no-ff` → tag → 自动部署（看门狗 `/tmp/autodeploy.sh <tag>`）→ 生产三重验证。
4. 每批结束在 `CHANGELOG.md` 记"性质/影响/根因/真假故障分辨"，并在本文档更新批次状态。
5. 遇到需要老板决策的点（定价、口径切主链路、是否砍旧引擎）→ 暂停该批、写明选项与影响，继续推进不依赖该决策的其他批次。

## 四、老板拍板结果（2026-09-18）与由此定稿的排期

1. **口径主链路：thsdk 暂不切明盘主链路。** → 口径漂移页（B5 已落地）**保持三源中立**，
   不把任一源设为"权威"，`DRIFT_FIELD_BY_SOURCE` 只声明"比的是哪个字段"，不改权重、不做校准。
2. **双 K 线引擎：先评估，再决定"合并功能"还是"优胜劣汰"。** → 评估已完成:
   **`docs/K线引擎评估_20260918.md`**，结论 = **以 `KlineChart` 为唯一内核，把 IK 的独有能力
   （分时模式 / 主力意图结构 / 分层开关）并入，随后淘汰 `InteractiveKline` + `MinuteLwcChart`**；
   分 P0 类型收口 → P1 能力补齐 → P2 逐页迁移（IndexBody→PaperTrading→AnalysisDetail→KlineModal，
   每页配 before/after 视觉+DOM 比对）→ P3 退役 + 新 ui-rules 规则（只允许一个 `createChart` 引导模块）。
   **排入 B5c**（P0+P1 先做，纯增量）与 **B8**（P2+P3 逐页迁移）。
3. **商业化：先做内部计量。** → **B7 收敛为**：按 skill/按用户/按天记录调用与耗时 + 用量看板
   （owner 可见），**不做**对外定价/账单/支付；接口设计为未来接计费留字段，但不暴露给用户。

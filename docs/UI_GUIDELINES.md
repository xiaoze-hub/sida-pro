> 覆盖：全站主题 token、共享基础组件、导航、页面标题/工具栏、首页、AI 对话、个股工作台、设置及生产 TSX 展示类；检查覆盖 `src`、`packages/base-ui`、`packages/biz-ui`。
> 未覆盖：交易算法准确性、外部行情接口可用性、生产数据与全部页面的完整业务验收；不以 UI 验证代替口径、权限和多用户测试。

本规范是新建或修改 UI 的统一入口。此前视觉研究文档仅供历史参考；冲突时按本规范执行。产品定位是基于现有数据的 AI 股票技术分析，表达分析证据、来源、时点和不确定性，不用“推荐”“稳赚”“现在买入”等营销话术包装分析入口。

## 1. 视觉方向

采用清爽的分析工作台：亮蓝作为唯一主交互色，白色内容面板与轻微冷色页面底形成层次；深色采用墨色页面底和更亮的内容面板。避免大面积紫灰、厚重蓝灰描边、霓虹光晕和装饰渐变。继续使用现有 Radix + Tailwind 基础组件，不再引入另一套组件库。

侧栏与工作区 Tab 的选中态使用淡底色、文字色和字重；禁止选中项左侧彩色竖条、彩色描边和圆角彩色边线。键盘焦点环是可访问性状态，仍需保留。

模块边界优先由空间、底色和分组建立。普通卡片只用 `border-border` 的细弱边线与 `shadow-panel`，禁止每层容器重复包卡片。`border-border-strong` 用于需要明显边界的弹出层等特殊场景；输入框用 `border-input` 保证辨认能力，不能为追求“无边框”牺牲可用性。

## 2. Token 与主题

- 颜色唯一来源是 `frontend/src/index.css`。页面底 `background/s0`，主内容 `card/s1`，内部辅助区 `s2`，选中区 `s3`，弹出层 `popover/s4`。组件使用语义 token，不能手写页面级十六进制配色。
- `background/card/popover` 分别别名到 `s0/s1/s4`。修改暗色与舒适模式时只能调整基础层，禁止另起一套同名组件颜色。
- 容器底色不透明，禁止 `bg-card/50`、`bg-background/80`、`bg-s2/40` 等叠色；禁止以 `border-border/30` 随意降低边界。状态色的小面积浅底和模态遮罩允许透明度。
- 主按钮固定使用 `bg-primary text-primary-foreground`，不能硬写白字；暗色主按钮也要满足对比度。
- 涨跌使用 `stock-up/stock-down`；中性指标不能染成涨跌。风险、成功、关注等只在有实际语义时用对应 token。
- 切换主题、密度、舒适模式统一通过 `setAppearance()`；同窗口组件、其他标签页与系统主题变化必须同步。舒适模式仅改变深色外观，不能覆盖浅色。
- 正文与次要文字相对内容底色至少 4.5:1；表单轮廓至少 3:1。深色卡片与页面底色必须能区分。`token-contrast.test.ts` 负责回归检查。

## 3. 字体、留白、密度

四级主字阶：页面标题 20px，区块标题/重要数值 16px，正文/操作 14px，辅助标签/数据来源 12px。生产界面禁止 10/11px 微字与任意 13px 字阶。公开介绍页可使用专门的大标题阶。

间距以 4px 为基数，卡片常规内边距 16px，模块间距 16–24px；内部数据组间距 8–12px。密度改变留白，不把文字缩到难以阅读。金额、价格和百分比使用等宽数字，保留业务单位及正负号。

## 4. Header、Toolbar 与数据组件

页面优先使用 `src/components/PageHeader.tsx`，包含以下区域，窄屏按自然顺序换行：

1. 一个明确的页面主标题；必要时一句描述。
2. 操作区：主操作最多一个实心按钮，次操作用 outline/ghost；刷新有可访问名称、加载态和禁用态。
3. 元信息区：更新时间、来源、市场状态。不能把交易时段、多个数据源、延迟等全部拼成一行细字。

`StatusChip` 用于短状态或上下文（例如“港股·已收盘”“数据源·需关注”“快照时间”）；不可点击的标签使用 span，可展开详情时外层必须为 button/PopoverTrigger，有展开状态且支持键盘、触摸和 Escape。完整交易时段、当地时间与源明细放在 Popover，不能只靠 hover/title。

价格、成交额、换手率等连续数值用定义列表或对齐网格，不能每个数值都套圆角 Chip。一组互斥视图用分段按钮或 Tabs，表达选中态；筛选条件用可移除 Chip 时需提供明确删除名称。无动作的状态不可伪装成按钮。

区块标题与操作在同一行，长标题允许换行；表格工具栏分离筛选和批量操作。文本超长可截断，但完整信息须有详情入口，不能仅缩字号。

## 5. 布局与浮层

市场全景使用分组式折叠标题（`presentation="group"`）及情绪、主线、温度三张独立卡片，各卡片按内容取高；分组外围不再套整张大卡。其他折叠模块使用 `presentation="panel"`，收起时只挂标题，双列在单项折叠时重新排布，不能保留空白列。

每个模块只有一个主要内容面板，内部优先分隔线/留白，避免“卡片套卡片”。图表与表格铺满所属内容区，主图与辅助栏在窄屏堆叠，不能固定右栏导致主图被挤出屏幕。

全局数据使用提示与数据源共用工作区状态行，桌面靠右对齐，窄屏自然换行；禁止另做漂移页脚或悬浮提示条。

个股 AI 分析入口使用 `CopilotCapsule presentation="inline"`，位于工作台工具区；旧保存的拖拽坐标不得影响内联入口。不允许新加常驻悬浮卡片压住数据。全站同一上下文只保留一个 AI 入口，ChatWidget 仍使用现有入口去重机制。

浮层只在用户操作后展开，使用不透明 popover 底和统一 overlay 阴影；不叠加彩色外发光。模态需有标题、关闭名称、焦点管理及 Escape。弹出后不能让底下工具栏穿透可见。固定导航、浮层和移动端安全区必须一起检查。

## 6. 可访问性、移动端、状态

- 所有操作可用键盘完成，焦点样式可见。Tabs 支持方向键/Home/End、正确的 tabpanel 关联和焦点移动；图标按钮有名称。
- 常规按钮至少 36–40px；触摸主要目标至少 44px。移动端输入保持 16px，允许浏览器缩放。
- 390px 宽度下页面不得横向溢出；长表格在自身容器滚动。工具栏换行，AI 会话列表使用可展开面板，不强塞桌面侧栏。
- 加载、无数据、错误、更新失败但保留快照分别展示。无数值显示 `--` 并提供“无数据/未取到”说明，禁止填 0 冒充缺失。不得为展示 UI 编造市场数字。
- 来源、基准日、资金口径标签必须保留；不得通过折叠/隐藏把业务口径约束移出用户可见区域。跨市场开闭市继续以后端状态为准。

## 7. 修改与验收

先复用基础组件与语义 token，再添加页面组合；确需新增模式时在此更新用途和边界。不要用各页 CSS 补丁创建新的视觉体系。

提交前执行：

```sh
pnpm --dir frontend typecheck
pnpm --dir frontend lint
pnpm --dir frontend test
pnpm --dir frontend ui:check
pnpm --dir frontend build
git diff --check
```

`ui:check` 检查主应用及两个 UI 包，包含字号、透明容器、弱化边线、主题别名和原有数据诚实性规则；Node 测试验证规则本身能拒绝错误例子。不得通过新增例外白名单绕过标准。

有视觉或布局变化时，用真实浏览器复核浅色、深色、390px 手机宽度，检查 Header、数据标签、主要操作、加载/错误/空态和浮层遮挡。截图放在忽略的 `output/playwright/`。若本地外部行情不可用，应如实记录验证限制；无数据布局检查不能称为真实行情验收。

变更需同提交更新 CHANGELOG。自动门禁负责客观约束，不能替代用户对整体视觉和操作体验的验收。

## 2. 各项改法与验收线

### F2 结构化证据（泳道 A，最高优先）

**改法**：新增 `src/core/evidence_pack.py`，从管线取数结果产出
`{evidence_id, tool, source, as_of, caliber, status(ok|missing|degraded), digest, run_id}`；
`chat.py` 的 `done` 载荷增加 `evidence[]` 字段（**只新增，不改 `evidence_audit` 现有语义**）。
`evidence_id` 形如 `{run_id}:{seq}`，与 `copilot_steps.seq` 同源。

**验收**：抽 20 条回答，正文中每个硬数字能在 `evidence[]` 找到唯一 `evidence_id`；找不到的必须落在 `missing`。**不许**用「审核通过率」当指标。

### F1 共享事实包（泳道 C 建、泳道 A 注入）

**改法**：`src/core/fact_pack.py` 产出可序列化的 pack（`pack_id` + `as_of` + 各标的
`quote{price,pct,vol,amt,source,caliber}` + `missing[]`），内部复用 `build_copilot_brief`；
`delegate_many()` 接收 `fact_pack`，子 run 继承同一 `pack_id`；
`pipeline.compose_prompt(..., fact_pack=None)` 在证据区顶部注入「本轮事实包冻结于 …，
不得引用晚于该时点的数据」。

**验收**：同一父 run 下 N 个子 run 的 `quote.as_of` **完全一致**（哈希断言）；子 run 重复取同标的时上游调用计数不增加。

### F4b 技能锁（泳道 C）

**改法**：`src/harness/skills.lock.json` 记 `{name: {sha1, chars}}`；`recipes.py` 加载时校验
`recipe.skills ⊂ lock`（缺失即报错，不再静默不注入）；`scripts/check_skills_lock.py` 做 CI 门禁（改 md 未同步 → 红）。

**验收**：故意写不存在的 skill 名 → 加载报错；改一行 md 不同步 lock → 门禁红。

### F3 审核阻断（泳道 D，Wave 2）

**改法**：L1 确定性阻断——对账未通过的硬数字标灰/不可复制；`evidence_missing` 非空的维度
不得出现结论句。**不引入第二个 LLM 审核员**。L2 保持「只有服务端 pending annotation 才上图」的现状。

**验收**：3 个反例（编造价位 / 口径冲突 / 缺数据给结论）全部被拦；只统计「反例是否被拦住」。

### F5 调度四档（泳道 B）

**改法**：`window_kind` 四档 + `interval_min` 盘中循环；沿用 `is_trading_day`（**不能退化**）；
每次执行写 `copilot_schedule_runs`（失败也写）；午休 11:30–13:00 不触发；跳窗不补跑。

**验收**：节假日不跑 / 午休不跑 / 单条失败不影响其他任务 / 记录页能看到失败原因。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| `pipeline.py` 被 A 独占，C 依赖其 `fact_pack` 形参 | 契约写死在两份任务书里；C 用 `try/except TypeError` 防御式调用 |

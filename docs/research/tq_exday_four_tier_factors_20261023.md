## 一、结论先说（三句话）

1. `get_exday_data` 的 `Amo`/`Vol` 是 **4 档 × 4 列矩阵**（=`[买入额, 卖出额, 主动买额, 主动卖额]`），
   产品过去只读了 `BCancel/BOrder` 两个标量，**整个四档结构 + 主动/被动拆分被丢掉了**。
2. 同一接口里的 `BOrder/TotalBOrder/SOrder/TotalSOrder/CJBS` 能算出**委托粒度**与**委托-成交笔数比**
   —— 这是 `.tck` 逆向做不出来的「被动拆单」的**日频代理**，零额外成本。
3. 但它 **只返当日 1 行**（count/start_time/date 全试过），所以历史必须**自建日采集器积累**；
   而 `get_bkjy_value` 的 BK5~BK19 十四张**板块日频序列**是真的有历史，产品一个消费方都没有。

### 2.2 委托粒度与拆单代理（同一行里的标量，产品完全没用）

| 指标 | 601318 | 600519 | 002361 |
|---|---|---|---|
| 买委托量 `BOrder` / 笔数 `TotalBOrder` | 1,402,448 手 / 68,017 笔 | 86,002 手 / 1,777 笔 | 1,005,819 手 / 27,903 笔 |
| **笔均委托（手/笔）** | 20.6 | 48.4 | 36.0 |
| 笔均成交（元/笔，=成交额÷`CJBS`） | 26,415 | 169,701 | 7,080 |
| 笔均委托折算（元/笔） | ≈26,500 | ≈646,000 | ≈36,000 |
| **委托/成交粒度比**（加权） | **3.97×** | **14.5×**（买侧 37.9×） | **3.12×** |
| **委托-成交笔数比** = (`TotalBOrder`+`TotalSOrder`)/`CJBS` | **0.686** | **0.208** | **0.998** |
| 买/卖撤单率 = `BCancel/BOrder`、`SCancel/SOrder` | 23.1% / 20.3% | 30.9% / 26.3% | 33.5% / 30.3% |

**读法（这才是新东西）**：委托笔数比 <1 表示「一笔委托被拆成多笔成交」——
茅台 0.21 意味着平均 1 笔委托对应 5 笔成交（大委托被动挂单被连续小单吃掉 = 被动 maker 拆单）；
002361 = 1.00 表示委托与成交一一对应（散户挂单被逐笔吃，无被动拆单结构）。
这与 `tdx-client-l2-extraction` 里 `.tck` 的终局结论**互补**：`.tck` 证伪了「被动 maker 委托号落盘」，
而日频笔数比恰好是那个缺口的**统计代理**，且零成本、有当日全市场覆盖。

### 2.3 历史能力（必须如实说）

```
count=1/5/30/250          → 行数恒为 1，dates=['20261023']
带 start_time/end_time    → 仍 1 行
带 date=20261020          → 仍返今日
```
⇒ `get_exday_data` 是**当日快照**。历史只能靠**日采集器落库**积累（`cancel_rate_sampler` 已是这个模式，
本方案是把它从「撤单率单标量」扩到「四档矩阵 + 委托粒度」）。**20 个交易日后**才谈得上分位/IC。

## 三、新因子设计（可直接算，公式给定）

> 统一前提：单位=元/手/笔；`caliber = "tdx_exday4"`（客户端四档口径，**按单笔成交金额分档**）。
> 与 `eastmoney4`（东财 push2 四档）、`tick`（腾讯逐笔 ≥30 万）**不可混用、不可互校**，
> 展示处必须标口径（`src/core/caliber.py` 规则）。

| # | 因子 | 公式 | 今日实测 | 为什么有信息量 |
|---|---|---|---|---|
| F1 | **散户化率** `retail_ratio` | `Amo[3][0] / ΣAmo[*][0]` | 002361 56.9% / 601318 21.3% / 600519 0.0% | 筹码在散户手里还是机构手里；妖股崩前该值冲高 |
| F2 | **特大单占比** `xl_share` | `(Amo[0][0]+Amo[0][1]) / 2 / 成交额` | 002361 2.4% / 601318 17.5% / 600519 19.6% | 大资金参与度的**结构**读数（不是净额） |
| F3 | **主力主动净额** `main_active_net` | `Σ_{i∈{0,1}}(Amo[i][2] − Amo[i][3])` | 002361 +528 万 / 601318 +16,158 万 / 600519 +5,190 万 | 只在特大+大档里算主动方向，比全档 `Zjl` 更贴「主力」语义；**与 `get_more_info.Zjl_HB` 是不同东西**（后者是环比） |
| F4 | **拆单隐匿度** `gran_hiding` | `笔均委托量(手/笔) / 笔均成交量(手/笔)` | 002361 3.12× / 601318 3.97× / 600519 14.5×（买侧 37.9×） | >1 越大 = 大委托被拆成多笔成交（隐蔽建仓/派发）；≈1 = 一一对应 |
| F5 | **委托成交笔数比** `order_fill_ratio` | `(TotalBOrder+TotalSOrder)/CJBS` | 002361 1.00 / 601318 0.69 / 600519 0.21 | <1 = 被动拆单强度（`.tck` 拿不到的那部分） |
| F6 | **撤单不对称** `cancel_skew` | `SCancel/SOrder − BCancel/BOrder` | 002361 −3.2% / 601318 −2.8% / 600519 −4.6% | >0 卖撤更凶=压盘恐吓；<0 买撤更凶=虚假托盘。`cancel_order_intent` 现在只有买侧 z，缺卖侧对称量 |
| F7 | **内外盘强度** `active_ratio` | `Σ(Amo[*][2]) / 成交额` | 002361 50.4% / 601318 55.3% / 600519 54.0% | 官方外盘率，可与 `get_intraday_profile` 的腾讯内外盘交叉（口径不同，冲突时以形态解释为主） |
| F8 | **板块资金分位** `sector_flow_pct` | `BK15` 主力净额 20 日分位 | 需标定 | 板块轮动从「当日涨幅」升级为「资金分位」，且**有历史** |

**组合因子（真正的"新"）**

- **筹码迁移** `chip_migration` = F3 主力主动净额 − （小档主动净额）
  → 正 = 大单进小单出（筹码向大资金集中）；负 = 大单出小单进（派发/散户接盘）。
  与用户口诀「内盘大+涨+高位=诱多出货」是同构的量化写法，但**用结构不用总量**。
- **隐蔽吸筹** = `gran_hiding > 1.5` **且** `cancel_skew < 0`（买撤更多）**且** 当日涨跌幅 < 2%
  → 用户 MEMORY 里「拆单伪装须逆势才算主力」的可计算版本（三个条件缺一不可）。
- **被动拆单强度** = 1 / `order_fill_ratio`，按 20 日 z 分位 → 新流动性因子，现有因子库里没有量价之外的微观结构维度。

## 六、风险与纪律（写在最前面，别踩）

1. **档位阈值无官方文档**：本文推断 小<5 万 / 中 5~20 万 / 大 20~100 万 / 特大>100 万，
   依据只有「茅台 row3≈0」+ 三票分布一致性。**上产品前必须再用 2 只 300 元以上、2 只 3 元以下标的对拍**，
   并把结论写回本文，不许口头默认。
2. **只当日**：任何「历史基线/分位/IC」在当前都不存在，必须写明「自 <采集起始日> 起积累」，
   禁止用当日结构冒充历史分位（这是本项目最敏感的一类幻觉）。
3. **口径三源不可混**：`tdx_exday4`（按单笔金额）≠ `eastmoney4`（东财 push2）≠ `tick`（腾讯逐笔）。
   三者同屏时必须各带标签；`require_directional()` 只对 `tick` 放行方向判定（既有铁律，不改）。
4. **17709 单线程**：25ms/票 × 5,580 = 140s，**只能进采集器**；请求路径仅限单票/少量自选。
5. **BK 表零文档**：BK15 之外的推测语义一律不进产品，宁可少一个能力，不可编一个字段名。

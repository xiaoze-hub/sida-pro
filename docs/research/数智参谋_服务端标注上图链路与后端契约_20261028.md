## 2. 后端事实（读取路径本轮已补齐可核验身份）

`GET /copilot/annotations`（2026-10-28 起）：

| 事实 | 说明 |
| --- | --- |
| 响应回显目标 | `symbol` / `market` / `period` —— 前端必须与当前 K 线逐字比对，不再靠"请求—响应配对" |
| 响应回显属主 | `user_id`（`null` = 全局行）。前端默认只画"本人 + 有确认动作"的行 |
| 响应回显动作 | `action_id` = `copilot_actions.annotation_id` 反查（本人动作）；`null` = 没有确认动作 |
| 严格模式参数 | `market_strict=1`（不做 A 股族归并）、`mine_only=1`（不含全局行）、`action_linked=1`（只回有确认动作的行）、`ids=1,2`（精确身份读取，非法 → 400） |
| 默认值不变 | 不传严格参数时行为与旧版一致（A 股族归并 + 本人或全局），不破坏既有调用方 |
| apply 响应 | `annotation_id` + `annotation{id,symbol,market,period,price,ts,label,color,source}`，与动作状态同一事务 |
| 未确认提议 | 只在 `CopilotAction`，读取接口查不到 ⇒ 结构上不可能上图 |
| 撤销 | 仍不可用：`rollback_action` 对 annotation 直接 400，且无 DELETE 接口 |

## 3. 剩余缺口（本轮无法在"前端 + 最小后端"内解决）

1. **标的类型（个股/指数）没有落库**：`kline_annotations` 无 `instrument` 列，读取也不回显。
   处理：`000001/399xxx/880xxx/999999` 及与深市个股同号的指数代码**默认拒画**，
   播报写明原因。要真正支持，需要 `propose` 写入 `instrument`（+ 迁移 + 回显 + 读取过滤）。
2. **周期语义**：`propose_scenario_annotations` 仍不写 `period`，`_apply_annotation` 默认 `1d`。
   处理：非日周期确认**如实说"落在 1d、当前 5m、未上图"**，不假装已上图。
   要真正支持，需要 propose 透传视图周期。
3. **HKS/US 标的的市场口径**：`propose` 的 `market` 来自聊天上下文（默认 `CN`），
   港股/美股页面是 `HK`/`US`，严格模式下会被判目标不符 → 拒画（如实播报）。
   需要 propose 按视图市场写入。
4. **撤销**：仍无服务端入口（§2 末行）。界面上只写"撤销不可用"。
5. **其它页面的标注**：`IndexBody` / `AnalysisDetail` 的图表不再显示参谋标注
   （它们此前走的是被删掉的"画全部行"通道）。要恢复需把这几个页面接到
   `useWorkbenchAnnotations`，并解决 `supportPressure` 与图层价位合并的来源标注问题 —— 本轮未做。
6. **历史数据**：迁移前 `applied` 的动作 `annotation_id` 为 NULL ⇒ 其标注行没有确认动作，
   按新契约不画（不猜测回填）。这是刻意的。

## 4. 前端实现（唯一通道）

| 文件 | 角色 |
| --- | --- |
| `lib/copilot/serverAnnotations.ts` | 契约事实表 `SERVER_ANNOTATION_CONTRACT`；严格解析（缺目标/属主/动作回显的行按行丢弃并计数）；`verifyRow`（属主 → 确认动作 → 目标 → 价位/方向）；`linesForTarget`（同向同价合并）；`parseApplyResponse`（只认 `annotation_id`）；`verifyAppliedRow`（id 对齐后再核对动作与内容）；`targetRefusal`（未登录/指数/同号代码）；`annotationsUrl`（默认严格模式） |
| `lib/copilot/annotationLedger.ts` | 按精确目标分键的内存账本 + 订阅 + 发布序号；`currentAccountId()` 读 JWT `sub`；不存本地价位、不写 sessionStorage |
| `lib/copilot/annotationLink.ts` | `requestAnnotations`（精确读取 → 核对 → 写账本）、`linkConfirmedAnnotation`（apply → 按 id 精确回读 → 核对 → 写账本；周期/标的不符只说"未上图"） |
| `hooks/useAnnotationSnapshot.ts` | `useSyncExternalStore` 订阅当前目标快照（换 key 立刻空） |
| `hooks/useWorkbenchAnnotations.ts` | 页面唯一接线：目标 → 读取 → 价位线（`price/kind/label` 逐字取自服务端行） |
| `pages/StockWorkbench.tsx` | 只用 `useWorkbenchAnnotations` 的 `priceLines` 驱动 `KlineChart.supportPressure`；状态带读同一个快照 |
| `packages/biz-ui/src/components/KlineChart.tsx` | 删除 `aiNotes` 自取自画通道；重绘依赖补 `props.symbol/props.market`（换标的立刻重画、不残留旧线） |
| `components/copilot/AnnotationLinkBar.tsx` | 念出：画了几条 / 服务端标注 id / 确认动作 id / 未上图原因 / 撤销不可用 / 一次性提示 |

**不变量**（都有测试）：
1. 本地价位（正文正则、罗盘、sessionStorage 历史行、旧事件 detail）没有任何入口能上图；
2. 未确认（只有 pending）读不到 ⇒ 不可能上图；
3. 画出的价位/标签/标的/周期/属主/动作全部逐字来自服务端行，并按 id 精确关联；
4. 换账号/换标的/换周期/换个股↔指数 = 不同 key，旧线与旧提示立刻消失，迟到响应不覆盖；
5. 指数图、`000001` 这类同号代码默认拒画；不可画的都给出原因，不静默。

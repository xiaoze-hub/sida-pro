# 通达信客户端(本机 TQ 网关)板块数据能力调研

> 日期: 2026-09-10 晚 | 场景: 板块热力图/异动实时数据源评估(老板提议"通达信客户端更快、不限流")
> 结论先行: **可用, 且批量能力远超 thsdk**；但两者"板块"目录口径不同(代码撞号不同义), 接入须先做映射。

## 1. 接入现状(已存在, 非新链路)

- 本机 Windows 跑 **通达信金融终端** `TdxW.exe`(装于 `c:\new_tdx64`), 自带 HTTP 服务监听 **127.0.0.1:17709**, 宿主网卡侧 `172.27.16.1:17709`, 生产容器(panwatch)已可达。
- 仓库已有 vendor: `packages/marketdata/src/marketdata/vendors/tq.py`(`_rpc`/`tq_rpc`, 地址自动发现; 生产注入 `TDX_QUANT_URL=172.27.16.1:17709`), 现用于个股快照/K线/公式(ZLJC 主力进出)。
- 客户端插件源码 `c:\new_tdx64\PYPlugins\user\tqcenter.py`(4118 行)即为服务端方法全集; 网关按白名单放行(未知方法报 `-32601`), **板块类方法多数已放行**。

## 2. 实测能力(2026-09-10 晚, 收盘后)

| 能力 | 方法 | 实测耗时 | 说明 |
|---|---|---|---|
| 板块目录 | `get_sector_list(list_type=1)` | 236-363ms | 返回 **587 个板块** {Code,Name}: 880xxx 概念/地区/风格 459 个 + 881xxx 二级行业 128 个 |
| 全板块实时价 | `get_pricevol(stock_list=[587])` | **84ms(容器内) / 324ms(本机)** | 每码 `{LastClose, Now, Volume}` → 涨幅=Now/LastClose-1 |
| 成交金额 | 公式 `AMO` 批量 | ~300ms/587 | `AMOW`=当日成交额(万元); 与单码快照 `Amount` 一致(881290: 156.6亿) |
| 成交量+5日均量 | 公式 `VOL` 批量 | ~230ms/587 | `VOLUME` / `MAVOL2` → **量比可自算** |
| 量比 | 公式 `SG-LB` 批量 | ~270ms | 直接给`量比`+MA5/MA10; 概念板块值偏大(实测 40+), 需校准 |
| 换手 | 公式 `HSL` 批量 | ~250ms | `HSL` 换手率% |
| 主力资金 | 公式 `ZJLX` 批量 | ~2.2s/587 | `主买净额`(万元, 881290 +7.9亿 / 代糖概念 -17.2亿) + 近5/10日流向 |
| 主力资金2 | 公式 `SUPAMO` 批量 | ~220ms | `主力资金`(万元) + 超大单占比% |
| 主力进出三档 | 公式 `ZLJC` 批量 | ~1.5-2.5s/587 | JCL/JCM/JCS 净量(仓库已标注"单位未校验", 仅作代理口径) |
| 板块成分股 | `get_stock_list_in_sector('881290.SH')` | ~270ms | 11 只, 标准 6 位代码带市场后缀 |
| 个股所属板块 | `get_relation('600519.SH')` | ~345ms | 返回 BlockCode/BlockName/BlockType(行业/地区/概念/风格) |
| 单码快照(含**涨速**) | `get_market_snapshot('881290.SH')` | ~230ms/码 | 含 `Zangsu`涨速 / 涨跌家数 UpHome/DownHome / Amount / 买卖盘;**不支持批量** |
| 板块日K | `get_market_data(['881290.SH'],'1d')` | ~260ms | 日线可用于回填/校验 |
| 板块分钟K | 同上 period=1m | ❌ | 本地**缓存陈旧**(实测仍在 2026-05-27), `refresh_kline` 无效 → 分时量比不可得 |

对照 thsdk(当前生产实时链路): 3 码快照 2.6s; 480 码全量约 10s(60s 缓存+单飞)。**TDX 全量涨幅+成交额+资金+量比 ≈ 3s 内**, 且为本地客户端无配额/限流问题。

## 3. ⚠️ 关键坑: 两套"板块"口径不同(撞号不同义)

- 同花顺(thsdk, 现生产库 `Boards` 480 条, `URFI` 前缀): **881155 = 银行**(今日 +1.47%)。
- 通达信: `get_match_stkinfo('881155')` → **881155.SH = 其他纺织**; TDX 银行类只有 三个板块(全国性银行/地方性银行/中小银行)。
- 名称对账覆盖率: 行业 **51/90**、概念 **157/390**(严格同名); 直接按代码对仅 18/90(且不可信 —— 撞号不同义)。
- 结论: **绝不能按代码映射**, 必须按"名称 + 成分股重合度"建一次性映射表(成分股两侧都能取: TDX `get_stock_list_in_sector` / thsdk `fetch_block_constituents`), 未命中的板块保留 thsdk 兜底。

## 4. 集成方案(待老板拍板)

- **方案A(推荐)**: 映射表(TDX↔同花顺, 名称严格 + 成分股重合度自动生成, 人工复核一次) → 热力图实时链路改 **TDX 优先**(pricevol + AMO/ZJLX/SG-LB 批量, ~3s/全量), 未映射/取数失败回落 thsdk; 涨速用"我们自己的 60s 轮询价差"自算(5 分钟窗口), 或对 Top N 异动候选调单码快照取官方 `Zangsu`。板块口径与大屏口径保持现状。
- **方案B**: 热力图直接用 TDX 587 板块原生目录(口径最干净、最快、全覆盖), 但板块详情/成分股/日线历史(board_daily)与页面持仓/同花顺口径分叉, 改造面大。
- **方案C**: 保持 thsdk 主链路, 仅把 TDX 作为**批量兜底/加速**(thsdk 抖动或限流时顶上), 改动最小。

## 5. 风险与未决

1. **陈旧快照防护**: 客户端未更新时 TQ 会返回旧数据却报成功(2026-09-03 生产事故教训) → 板块链路同样要带新鲜度校验(如 `get_more_info.HqDate` / 日K最新日期)。
2. **依赖客户端常开**: 生产 TQ 链路已依赖 TdxW.exe; 板块链路加入后该依赖加重(failover 设计需保留)。
3. **单位/口径校准**: ZJLX 主买净额 vs thsdk 主力净流入定义不同(代糖概念 -17.2亿 vs -8.4亿), 展示层需明确口径或换算, 不混用。
4. **涨速批量缺位**: 单码快照 230ms×480≈2 分钟不可行 → 自算(方案A)为准。
5. 公式历史值(return_count>1)返空(仓库既有结论), 只能取最新一根。

## 6. 复现

- 探测脚本(一次性): `%TEMP%\probe_tq_blocks.py` / `probe_tq_blocks2.py`(本机)。
- 最小验证: `POST http://127.0.0.1:17709 {"id":1,"method":"get_pricevol","params":{"stock_list":["881290.SH"]}}`。

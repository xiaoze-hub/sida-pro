## 0. 结论速览

1. **审计报告 B1 的"qfq 与不复权混存"模型需要修正**：实测 69,154 个 (symbol, date) 格子上，tencent/eastmoney/sina 三源 close **逐格相等、零差异**。原因在 `klines_ingestor.py:73-83`（P2-19, 2026-09-05）：**单链拉一次、同一份数据写三个 source 标签**。`source` 列在存量数据里没有区分度。取数口径实为**前复权**：腾讯 `fqkline/qfq`（packages/marketdata/vendors/kline.py:78）、东财 `fqt=1`（:212）；新浪不复权兜底只在运行时内存路径（kline_collector.py:696-726），不写 PG。
2. 但表**确实被污染，且是四类独立污染**，比 B1 设想的更广：
   - **A. 相邻柱复权基准漂移**（B1 担心的问题，已实际存在）：主板 19 个"物理不可能缺口"（超出 ±10% 涨跌幅边界 0.5~1.6%），涉及 11 只股票，散布 2023-06 ~ 2025-04；
   - **B. 同日双柱**（ts 时区约定切换残留）：537 个 (symbol, date) 键有 00:00+08 与 08:00+08 两个 ts 各 3 行，其中 **708 行是平线占位柱**（OHLC 全相等、volume=0，全部落在 08-31~09-04）；**09-07/09-08 仍有 55 只/日的同值双柱，污染持续发生中**；
   - **C. volume 单位混用（手 vs 股，×100）**：86 只可比股票中 **46 只**在 2026-08-28→08-31 整体 ×100；另有 58 只合计 85 个 ×20+ 跳变散点；
   - **D. qfq 基准冻结**（B1 原机制，尚未发作、必然发作）：历史段 = 2026-08-17~24 回灌时的 qfq 基准，之后逐日追加"当日基准"行，`ON CONFLICT DO NOTHING` 使旧基准永不重算。勘查窗口（08-18~09-08）内未发现已发作的除权假缺口（6-7 月分红季在回灌之前），**首只发生除权除息的自选股即出现假断层**。
3. **表结构与方案/审计记载有三处出入**：日期列是 `ts`(timestamptz) 而非 `trade_date`；唯一键 `(symbol, market, period, ts, source)` **已含 `period` 列**；**没有 `amount` 列** → 方案里的 dev 判据（`|amount/volume − close|/close`）**在此表上不可执行**，本次改用"涨跌停边界缺口判据"替代（见 §2A）。
4. **结论：B1 必须走「加列 + 全量重刷」**，"只重刷污染区间"不可行（理由 §4）。

## 2. 四类污染的证据

### A. 相邻柱复权基准漂移（19 个物理不可能缺口）

判据：主板（60x/00x，涨跌幅 ±10%）相邻两根 K 线的 `|open/prev_close − 1| > 10.5%`（间隔 ≤5 个日历日，排除长假；创业板/科创板 ±20% 无法用此判据，单列）。主板开盘价不可能超出前收盘 ±10%（除权日按除权参考价另算），超限即序列内部口径不一致。

**19 个缺口点，11 只股票**（剔除 08-31 之后 9 个双柱伪影，见附A）：

| symbol | 缺口日 | gap% |
|---|---|---|
| 600639 | 2023-08-28 | +10.6 |
| 601138 | 2023-10-23 | −11.6 |
| 600502 | 2023-10-25 | +11.7 |
| 600519 | 2023-11-01 | +10.8 |
| 600639 | 2024-01-25 / 01-26 / 01-29 | +11.3 / +11.2 / +11.1 |
| 603259 | 2024-03-07 | −10.8 |
| 603823 | 2024-05-07 | +10.5 |
| 600639 | 2024-02-05 / 02-06 | −10.9 / −11.0 |
| 603259 | 2024-09-30 | +10.7 |
| 600183 / 601138 / 601168 / 601899 / 603993 | 2025-04-07 | −10.7 ~ −10.9（当日全市场暴跌，其余板块跳空为真实行情） |
| 601138 | 2025-04-10 | +10.7 |

**一字板互证（600639，2024-01 浦东行情）**：01-25/26/29 三根一字涨停板（open=high=low=close，交易所定价、绝对真值）。真实涨停链必须满足相邻收盘精确 ×1.10：`9.96 → 10.96 → 12.06 → 13.27`；存储序列却是 `9.85 → 10.96 → 12.19 → 13.54`，相邻比率 **×1.112、×1.112、×1.111 连续复利漂移**（三日累计 +37.6% vs 真实 +33.1%）。600519 的 2023-11-01 柱同样：open=high=1696.48、量能 4.7 倍（提价公告日真实巨量），但缺口超限 0.8 个百分点。**结论：序列内部存在 ~0.5–1.6% 的柱间复权基准漂移，不是行情，是数据。**

### B. 同日双柱（ts 时区约定切换残留）

- `klines_ingestor.py:101` P2-19（2026-09-05）把 ts 从 `UTC 午夜`（= CST 08:00）改为 `CST 午夜`。切换前后**两套约定写的行 ts 不同、唯一键不同、互不去重** → 同一交易日两根柱。
- 实测 **537 个 (symbol, date) 键有 2 个 ts**（各 3 source 行）：08-31~09-04 每日 85-86 只全量双写；**09-07/09-08 仍有 55 只/日双柱**（抽查 000636/000759：两 ts 行**同值真柱**）——**截至勘查日污染仍在发生**。
- 其中 **708 行平线占位柱**（open=high=low=close 且 volume=0，OHLC=当日开盘或昨收，全部落在 08-31~09-04）：系盘中某次 fetch 拿到未完成快照被当日固化。样例（000938，08-31 两柱并存）：
  ```
  2026-08-31 00:00+08  o=34.86 h=39.47 l=34.86 c=38.95 v=267,043,500   ← 真柱（新约定）
  2026-08-31 08:00+08  o=34.86 h=34.86 l=34.86 c=34.86 v=0                ← 占位柱（旧约定）
  ```
  占位柱成为"当日最后一根"时，次日涨跌幅全部算错（如 000938 09-01 "+11.0%" 实为对占位柱 close 34.86 计算，真实隔夜变动 ≈ −0.6%）。

### C. volume 单位混用（手 vs 股，×100）

- 腾讯 fqkline volume 单位=手、东财=股；Engine 约定=股。vendors/kline.py:108 的手→股换算注释日期 2026-09-04，但生产数据实证单位切换发生在 **2026-08-28→08-31**（08-31 部署）。
- 86 只有 08-28/09-01 双日可比的股票中：**46 只 ×100 切换**（08-28 为手、09-01 为股，名单附B），39 只前后一致（后加自选或当时恰由股单位源供数），1 只不可比。样例 000725 京东方：08-28 = 10,338,636（=1.03B 股 ÷100）→ 08-31 = 1,378,303,300 股。
- 全史 ×20+ 跳变普查：**58 只共 85 点**。除 08-31 主体（47 点）与 09-02/03 各 7 点外，2023-06~2026-07 还有 **22 个单点散布**（与 §2A 的分段/异源拼接疑点同源，见 §5）。
- 影响：跨 08-31 边界的量比、换手率、OBV、筹码分布、量价共振类指标对这 46 只全部失真 ×100。

### D. qfq 基准冻结（B1 原机制，尚未发作）

- 机制：qfq 序列的复权基准随每次 fetch 的"最新除权事件"变化；ingestor 每日重拉 800 日但 `DO NOTHING` 使历史行保持首次写入时（T0≈2026-08-17~24）的基准，只有新增日期按当前基准写入。**任何一只自选股发生除权除息，其序列即在除权日出现假断层**，且永不自愈。
- 勘查窗口（2026-08-18~09-08）内：主板不可能缺口 19 点全部早于 T0，双柱伪影 9 点与除权无关，**未发现已发作的除权假缺口**（6-7 月分红季整体在回灌之前）。D 类是"必然而未至"。

## 4. 结论：B1 = 「加列 + 全量重刷」

**只重刷污染区间不可行**，理由：

1. **污染不以连续区间存在**：A 类是 19 个散点（跨 2023-2025），C 类另有 22 个历史散点，无法用"除权日附近"之类的区间规则圈出；
2. **D 类基准冻结是全局性质**：83 只股票 2023-04~2026-08 整段的 qfq 基准钉死在 T0，增量清洗在 `DO NOTHING` 下永远无法重算历史基准；
3. **C 类单位断层覆盖 46 只股票的全部 2023-04~2026-08-28 段**（该段以手计），只有全量重灌才能统一为股；
4. **成本可忽略**：209K 行 / 95 只，全量重刷 ≈ 一次 `--backfill 800`（分钟级），远小于精确圈区间的工程量。

**B1 落地时的配套前提**（动生产前须老板确认节奏）：
- `klines` 加 `adjust` 列（`none|qfq|hfq`）并纳入唯一键；ts 规范化为唯一约定（CST 午夜）；ingest 侧加 volume 单位断言（必须为股）；
- 写入改 `ON CONFLICT DO UPDATE`（或重刷前清表），否则基准依旧冻结；三源**真分源拉取**（P2-19 自记 TODO），恢复 source 列语义；
- 三个读取方补"按日期去重"（`_pg_fallback` 还需补 source 过滤）；建议 data_quality_sentinel 增加规则：主板相邻柱缺口超涨跌幅界限 → 告警（本次 19 点正是该拦的）；
- 重刷验收 = 本报告三条 SQL 复跑归零：双柱键数 = 0、×20+ volume 跳变仅剩真实异动、主板不可能缺口 = 0。

## 5. 无法判定的部分（诚实项，未联网、未动生产）

1. **A 类 19 缺口的精确成因**。候选：(a) 腾讯/东财对同一股票的 qfq 因子链存在 ~1% 级分歧（分红方案记录差异或因子舍入链），而 engine 按日择源（P2-19 单链）造成相邻柱异源拼接；(b) vendor 对柱应用因子时错位一天（600639 一字板揭示的"逐日复利漂移"更像此类）。两者都需要外部真实价格对账或 engine 择源日志。**DB 内三源标签同值，当日实际由哪个 vendor 供数的信息已丢失。**
2. **19 个缺口日是否恰为除权日**：未查外部分红日历。从日期分布看多数不在分红季（6-8 月），倾向于与除权无关，但不能排除。
3. **双柱写入方的精确时间线**（哪个进程/容器在何时写 08:00 柱；占位柱来自哪次盘中 fetch）：DB 无写入时间列，需生产容器日志与 08-31 前后部署记录对照。
4. **09-08 之后双柱是否停止**：勘查截止时仍在发生（55 只/日同值双柱），需次日后复查；若持续，B1 重刷前需先修写入侧。
5. **22 个历史 volume 散点**哪些是真实异动（短期停牌复牌）、哪些是分段拼接伪影：需外部对账。
6. **WDC（US）21 行止于 08-28** 的原因（掉出自选或源失败）未查；量级可忽略。
7. 方案 dev 判据（`amount/volume` 对比 close）因表无 `amount` 列未执行；若 B1 重刷时补该列，建议把 dev 判据一并接入 sentinel。

## 附C：关键 SQL（可复跑验收）

```sql
-- 1) 双柱键数（重刷后应为 0）
SELECT count(*) FROM (
  SELECT symbol, market, ts::date AS d FROM klines
  WHERE market='CN' AND period='1d' GROUP BY 1,2,3 HAVING count(DISTINCT ts)>1) t;

-- 2) 主板不可能缺口（重刷后应为 0）
WITH g AS (SELECT symbol, ts::date AS d, open, lag(close) OVER w AS pc, lag(ts) OVER w AS pts
  FROM klines WHERE market='CN' AND period='1d' AND source='tencent'
    AND symbol NOT LIKE '30%' AND symbol NOT LIKE '68%'
  WINDOW w AS (PARTITION BY symbol ORDER BY ts))
SELECT * FROM g WHERE pc>0 AND (d-pts::date)<=5 AND abs(open/pc-1)>0.105;

-- 3) volume ×20+ 跳变（重刷后应仅剩真实停牌复牌类）
WITH g AS (SELECT symbol, ts::date AS d, volume, lag(volume) OVER w AS pv, lag(ts) OVER w AS pts
  FROM klines WHERE market='CN' AND period='1d' AND source='tencent'
  WINDOW w AS (PARTITION BY symbol ORDER BY ts))
SELECT * FROM g WHERE volume>0 AND pv>0 AND (d-pts::date)<=5
  AND (volume::numeric/pv>20 OR volume::numeric/pv<0.05);
```

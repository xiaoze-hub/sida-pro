# SIDA-Pro 全界面 UI 合理性与字段排版审计 · 重构规划

> **审计对象**：`https://www.sida.hengsheng-elec.com`（生产，`v0.15.1`，PG `postgres:5432/sida`，2026-10-18 周日 12:00–12:40 CST）
> **代码基线**：`/home/ubuntu/sida-pro` @ `955754d`（`main`；工作区另有 25 个已修改文件与 20 个未跟踪产物，本次审计**未改动业务代码**）
> **视口**：1680×1050（桌面终端口径，DPR=1）；另以 1600×1000 跑布局体检探针
> **方法**：Playwright 登录态遍历 13 个路由 / 25 个页面状态（含机会页 7 个工具 Tab、工作台 6 个 Tab + 速览）→ 全页截图 + DOM 文本 + 版面度量；关键字段回查 API 原始 JSON 做「UI 空 vs 后端有没有」交叉核验；两次采样（首屏 ≈9s、稳态 ≈20s）区分「加载中」与「真缺失」
> **证据目录**：`docs/research/shots_ui_audit/`（38 张全页截图 + 同名 `.txt` DOM 文本）

## 0. 一句话结论

**这套系统的数据深度是够的，问题几乎全部出在「最后一公里」：数据到了前端却没被读、读了却读错、读对了却被 800 个 `--` 和 400 行表格埋掉。**

1. **字段缺失 1028 处，归并为 24 类**：16 类是上游 null / 未实现（可以用空态说清），3 类是**口径或单位错误**（温度缺项按 0、净量 0 位舍入、代码前缀泄漏），4 类**本就不该占位**（非涨停无封单、ST 无竞价、未发起预测、过期建议），1 类是可 join 的后端缺口（梯队涨跌幅）。
2. **比缺失更严重的是「有数但错」**：机会页 30 条 active 信号里 **10 条止损价高于入场价**（做多逻辑不成立）、**评分 23 条 100 / 7 条 99**（排序失效）、**30 行只对应 9 只股票**（重复 3–4 倍）。
3. **「看图决策」在 3 个页面上失守**：题材情绪页 1,587 个描边元素 + 829 个 `--`；竞价页 436 行不分页（全页 16,784px ≈ 16 屏）；研究页 5,728px，其中 3,077px 是整篇未折叠的深度分析全文。
4. **巨型单体确认**：`Opportunities.tsx` 2,278 行、`export default function` 内部 1,919 行无子组件；`L2Tab.tsx` 1,316 行、单页 7 个纵向 Section。
5. **自动化布局探针（首页 / 机会页 / 工作台三个代表页）0 重叠 / 0 真裁切 / 0 横向溢出**——版面「没坏」，坏的是**信息预算与取舍**。这是设计问题，不是 bug 问题，因此本规划按「先修数据可信度 → 再砍信息量 → 最后拆文件」排序。

### 3.2 四类「`--`」必须区分开（本次最核心的规范缺口）

现状：**加载中 = `--`、真缺数 = `--`、不适用 = `--`、源故障 = `--`**，四种语义共用一个字符。实测证据：

- 工作台·盘口：**9s 时 27 处 `--`，22s 时反而变成 48 处**（更多 Section 渲染出来，其中一部分随后被真实值替换）。用户在首屏 20 秒内看到的 `--` 里，多数并不是「没有数据」。
- 建议 Tab：9s 时「三层滤网」三行全是 `加载中...`，22s 后只剩「情绪层 `--`」一处。
- 新闻 Tab：代码注释与页面文案都承认「列表为空时『确无内容 / 取数失败 / 首拉在途』不可区分」。

> 建议落成组件契约（§8.6）：**加载态永远不输出 `--`**，改用固定宽度骨架条；`--` 只保留给「确实没有」且必须带 `title` 原因；区块级缺数用已有的 `MissingFields` 聚合（该组件已存在，但全站只有 L2Tab 用了 2 处）。

## 4. 数据正确性问题（比「缺失」更伤信任）

### 4.1 机会页：可执行计划在数学上不成立

从 `GET /api/recommendations/strategy-signals?status=active&limit=500` 取全量 active 信号（30 行）：

| 检查项 | 实测 | 结论 |
|---|---|---|
| `stop_loss >= entry_high`（做多止损高于入场） | **10 / 30** | 计划不可执行 |
| 唯一标的数 | **9**（30 行 → 每只重复 3–4 次） | 列表被重复项灌水 |
| 评分分布 | **100 分 ×23、99 分 ×7** | 排序/筛选失效 |
| `confidence == score/100` | **30 / 30** | 置信度是评分的副本，零信息量 |
| 方向 | 30/30 `buy`，但 `direction=null` | 动作字段两套并存 |

实例（UI 与 API 一致）：

| 标的 | 入场区间 | 止损 | 目标 | 问题 |
|---|---|---|---|---|
| 寒武纪 688256 | 905.85 ~ 924.15 | **938.71** | 1,143.24 | 止损高于入场上限 1.6% |
| 中际旭创 300308 | 663.30 ~ 676.70 | **791.96** | 965.24 | 止损高于入场 17% |
| 永鼎股份 600105 | 28.40 ~ 28.98 | **36.17** | 47.14 | 止损高于入场 25% |
| *ST广糖 000911 | 5.544 ~ 5.656 | 4.383 | 7.247 | 风险股进入「建仓」池 |

**建议**：后端在落库前加断言 `entry_low < stop_loss < target_price`（做多）；不满足则降级为 `watch` 并标注原因。前端表格对不合法行加 `data-invalid="1"` + 红色左边条 + tooltip。信号按 `(symbol, snapshot_date, strategy)` 去重后再入库。

### 4.2 集合竞价：量比量纲错到 5 位数

- 第 1 行长鑫科技：`竞价量比 74898.0 倍`；第 4 行新华传媒：`163513.0 倍`；全表 857 ~ 163,513 倍。
- 正常量比应在 0.5–20 区间。`src/core/auction_pool.py:284` 把 TQ `OpenVolPre1` **原值透传**（`round(float(vr), 2)`），未做量纲校验，疑似该字段本身是「万分位/基点」或「竞价量 ÷ 单笔均量」。
- 同表 `撤单率 68.7%–99.1%` 也整体偏高，需与 TQ `撤单量/委托量` 口径对齐。

> 这是**看起来最像真实数据、实际最不可用**的一列——用户会据此判断「爆量抢筹」。

### 4.3 暗盘 TOP：浮点被显示成 0

`safeFixed(r.main_net_vol, 0)` → `0.4661` 显示 `0`、`1.5526` 显示 `2`。5/20 行净量为 0，用户会误判「无净量」。同表 `main_net_ratio` 与 `main_net_vol` 数值完全相同（如 `0.4661/0.4661`），两列重复。

### 4.4 口径对照：「0」与「未留痕」混用

`2026-09-28 / 09-29 / 09-30 / 10-14` 的「明盘 L2 主力净流入」显示 `0`，而同表 10-08/10-09 显示「该日未留痕」。**`0` 与「未留痕」在同一列混用**，用户无法判断这是「当天净额恰好为 0」还是「采集失败写成了 0」——违反项目自己的「缺数给 `—` 不给 0」原则。

### 4.5 首页市场温度：缺项按 0 仍然给出 100

同屏：`晋级 --`、`封板率 --`，温度盘却是 **100**。卡片自带口径「高度×15 + 晋级率×40 + 封板率×45(缺项按0)」——高度 11 已足以顶到上限。**三项缺两项时不应出分**，应显示「数据不足，暂不算温度」。

### 4.6 代码前缀泄漏

- 竞价表：`USHT603922`、`USHT600243`…
- 问财表：`USZA000006`、`USZA000012`…

内部符号（`US` + 交易所 + 代码）直接进了「代码」列，破坏复制/跳转/搜索。建议在 `@/lib/format` 增加 `normSymbol()`，表格列统一走它。

### 4.7 研究页：1 个样本给出 100% 命中率

TradingAgents 历史表：`总命中率 100%`、`卖出 (1) 100%`、`买入 (0) -`。单样本百分比无统计意义，应与账本页一致——样本 < 5 直接给「样本不足」。

## 5. 逐界面走查

### 5.1 首页 `/`（2.7 屏，12 个区块）

**首屏顺序**：市场情绪条 → 5 张指数卡 → KPI 带 → 情绪周期 / 主线 Top6 / 市场温度（三栏）→ 共振精选 30 条 → 异动池 → 涨跌分布 → 今日要紧事 → 最新报告 → 机会发现。

**问题**
1. **P2** 12 个区块等权重平铺，没有「今天最重要的一件事」。首屏最有价值的其实是「市场情绪 + 主线」，但被 5 张指数卡和 4 个 KPI 挤到第二屏。
2. **P1** 封板率/晋级/成交额/跌停 4 个空值混在情绪条里，用户无法判断「今天是数据没出来，还是市场没数据」。

### 5.2 题材情绪 `/theme-mood`（2.0 屏，**829 处 `--`，1,587 个描边元素**）

**这是全站最严重的一页。**

| 指标 | 实测 |
|---|---|
| 首屏出现正文耗时 | **≥20s**（7s 时仍是 spinner，26s 抓取才有正文；`board` 响应 837KB + `ladder` 271KB） |
| `--` 数量 | 829（≈820 来自梯队个股涨跌幅） |
| 描边元素 | **1,587**（网格每个 cell 都有 border） |
| 10.5px 以下元素 | 2,978 |
| 后端字段 | `ladder.ladder[*].rows[*].stocks[*].pct` **1,222/1,222 全 null** |

**为什么这页最伤**：用户来这里是为了「一眼看出哪个题材在升温」。现在他看到的是 20×N 的深色格子墙，每个格子里是「股票名 / `--` / S」，需要逐格读名字。这正好违背「看图决策，不做数据堆砌」。

**根因**：`LadderBoard` 用 `s.pct != null ? fmtPct : '--'`；`ladder` 接口不返回 pct，而 `board` 接口的 `core_stocks.pct` 是有的（如冰山冷热 `9.9567`）。**同一后端、两个接口、一个有一个没有**。

**修法（不改版式也立刻见效）**：
1. 后端 `ladder` 补 pct（从 `core_stocks` join 或当日 K 线）；
2. 前端缺 pct 时**不渲染 `--`**，改为「只显示名称 + 板数」，格子高度不变；
3. 网格 cell 去掉 border，用 1px gap + 背景明度表达（网格描边降到 0）。

## 6. UI 合理性专项

### 6.1 「看图决策」的实际占比

| 页面 | 图表/图形占比 | 文字与表格占比 | 判定 |
|---|---|---|---|
| 板块热力 | 95% | 5% | ✅ 样板 |
| 工作台（带2） | 48%（含图例文字墙） | 52% | ⚠️ 图例应折叠 |
| 首页 | 35% | 65% | ⚠️ 区块过多 |
| 盘口资金 | 10%（双条） | 90% | ❌ 表格堆 |
| 题材情绪 | 60%（但全是格子） | 40% | ❌ 有图形无信息 |
| 竞价 | 0% | 100% | ❌ 纯表格 |
| 研究/基本面 | 0% | 100% | ❌ 纯文本/表 |

### 6.2 卡片化与 hairline

| 页面 | 描边元素 | 10.5px 以下元素 | 问题 |
|---|---|---|---|
| 题材情绪 | **1,587** | 2,978 | 每个矩阵格一个 border，形成「铁丝网」 |
| 集合竞价 | 460 | 2,207 | 每行多处分隔线 + 10px 文字 |
| 基本面 | 115 | 11 | 表格 hairline 正常 |
| 首页 | 95 | 301 | 区块 border 正常，但 12 块同权 |
| 工作台盘口 | 60 | 17 | 合格 |

**结论**：项目没有「卡片化过重」，反而**卡片化不足 + hairline 滥用**——用描边代替了层级。设计系统规定「平铺面板用 hairline、浮层用唯一阴影」，但没规定「一张屏最多几层 hairline」。

### 6.3 字阶与密度

- 全站字号集中在 10/11/12px，符合设计系统 6 档；但题材/竞价页 10px 元素超过 2,000 个，**字号合法 ≠ 可读**。
- 首页/机会页的 4 格 KPI 排布重复出现两次，形成「仪表盘模板感」。

### 6.4 导航与重复入口

- 一级导航 **7 组 21 项**（数智参谋 + 行情 4 + 机会 4 + 决策 3 + 报告 1 + 个人中心 4 + 系统 5）；`报告` 与 `研究` Tab、`暗盘资金` 与 `主力战报`、`持仓` 与 `影子账户` 语义相邻却分属不同组。
- 首页「机会发现」、机会页、工作台「洞察」三处都能进同一标的，路径不统一（一处跳工作台、一处开抽屉）。
- 「数据能力 13/18 · K线截图、事件日历 等4项」常驻侧栏底部，是运维信息，不应占产品导航位。

### 6.5 一致性

- 日期格式三套：`2026-10-16`、`20261016`、`10月16日 15:32`。
- 金额单位混排：`+9.56亿` / `+4624.54万` / `-38.3亿`（同屏可接受），但「净量」无单位、「量比」无单位。
- 涨跌色用法正确（仅数值/涨跌），未发现背景染色。

### 6.6 拥挤度判定

**结论：不是「挤」，是「没有取舍」。** 全站横向 0 溢出、0 重叠，说明栅格本身是健康的；真正的问题是每个区块都要求「完整展示」，于是页面只能向下长。

| 拥挤度 | 页面 | 判据 |
|---|---|---|
| **过载** | 集合竞价（16 屏 / 436 行）、题材情绪（829 个 `--` / 1,587 描边）、研究（5.5 屏）、基本面（3.9 屏）、问财（3.0 屏） | 单页 > 3 屏，或单表 > 60 行 |
| **偏密** | 工作台盘口（2.3 屏 / 7 Section）、决策账本（2.4 屏 / 10 表）、首页（2.7 屏 / 12 区块）、战报（2.6 屏） | 单页 2–3 屏，区块 ≥7 |
| **合适** | 板块热力、口径对照、持仓、AI 参谋、暗盘 TOP | 单页 ≤1.2 屏 |

三条根因（对应 §7 的合并/拆分）：
1. **没有分页/折叠**——竞价 436 行、龙虎榜 68 行、分红 13 行、资金流水 30 行全部展开；
2. **缺数块占满面积**——明盘 30 天空表 828px、68 行空原因列、封单成色 6 个 `--` 占 370px；
3. **区块等权**——首页 12 块、盘口 7 段、账本 10 表，没有任何一块被明确判为「主视觉」。

   否则用户看不到「这里曾经有一条倒挂计划」，也就无从判断生成端坏了。动作/分数已降级，不可执行这一点由 `plan_valid=false` 表达。
2. **缺口比值不逐行试算量纲**：假如逐行按「哪个倍率落进 0.3~30 就用哪个」，同一列会混着 bp 与 pct 两种口径 ——
   那是另一种量纲错乱。规则固定为「原值 → ÷10000 万分位 → 置空」，宁可缺。
3. **`pct` 缺失时不留 `--`，保留等高占位**：审计要求「不渲染 `--`、格子高度不变」，故用 `h-[14px]` 空块而非删列。
4. **顺带修了 `USHT` 前缀导致 TQ 增强整批跳过**：`_normalize_symbol` 只认 USZA/USHA/USTM，沪市前缀让
   `len(sym)==6` 判断失败 → 竞价额/量比/撤单率对沪市整批为空。这属于同一根因（F19），一并修。

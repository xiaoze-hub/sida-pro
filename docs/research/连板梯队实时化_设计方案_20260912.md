## 2. 目标与非目标

目标（老板六条）：
1. 题材表可折叠；梯队移到题材表**上方**（打开页面即见梯队）。
2. 梯队横向滚动**默认停在最新一天**。
3. 梯队列头日期全格式 `2026-09-11`。
4. 每日列内标记 **首板 / 炸板 / 断板**（首板=1板组显式加字样；炸/断见 §3 口径）。
5. **盘中实时跟踪，收盘定型**：交易时段内 60s 刷新盘中态；15:05 后切收盘真值并覆盖盘中态。
6. 每股一根**当日红绿 K**（红=收≥开，绿=收<开）+ 名称 + 涨幅 + 首封时间。

非目标（YAGNI，明确不做）：
- 不新建 PG 表、不做盘中轨迹回放（老板已否新增表）。
- 不改 `seal_sampler` 现有行为（封单成色功能保持原样）。
- 盘中不区分「封死」与「涨停价排队」（无盘口买一量证据，见 §3.2 诚实标注）。
- 不做梯队的多视图（实时天梯/经典天梯/列表天梯等参考图页签）——老板未要求。

## 3. 口径

### 3.1 三态（盘中，每 60s 一轮）
对候选宇宙（= 昨日定型梯队成员 ∪ 本轮 TDX 扫描在板股 ∪ Redis 态里今日曾上板股）逐股判定：
- `sealed_now`（在板）：`price == limit_price(prev_close, 板块/ST 规则)`（`limit_rules` 现有模块算涨停价；容差 1 个最小报价单位）。
  **诚实标注**：盘中只证明"价格在涨停价上"，封死/排队不分；UI 文案用「在板」不用「已封死」。
- `blown`（炸板）：今日 Redis 态里曾 `sealed_now`，本轮 `price < limit_price`。
- `broken`（断板）：昨日定型 `boards ≥ 2` 且收盘封板，今日**未触**涨停价（本轮不在板且今日从未在板）。
  **昨首板今未续 ≠ 断板**（只算淘汰，不标）——避免把普通首板次日回落糊成"断板"。

### 3.2 收盘定型（15:05 起 / 非交易时段）
- 梯队与三态全部以 `limit_up_events` 为准：touched 且 `is_sealed_close=False` → 炸板；昨日封板今日无 touch → 断板。
- 定型结果**覆盖**盘中态；Redis 当日态在定型后 TTL 自毁（不再读）。
- 首板 = 定型 `boards == 1`（1板组头加「首板」字样）。

### 3.3 更正记录（对拍板答案的事实修正）
拍板时推荐"复用 seal_quality_samples 推炸板"。勘查发现 `seal_sampler` 每 tick **只采 30 只**，
而日均涨停池 60~120 只 → **覆盖不足，单独用它推炸板会漏标**。
修正：盘中轨迹主链 = 本方案新增的 60s TDX 扫描写 **Redis 态**；`seal_quality_samples` 仅作**补充证据**
（该股若有采样且采样显示开板，可佐证 blown），seal_sampler 本身不改。

## 4. 架构与数据流

```
[60s job ladder_live_tick]（交易时段内；startup.py 注册，风格同 seal-quality-sampler）
   TDX get_pricevol 全 A 股分批(≈1s/轮) ──> 涨停价判定 ──> 三态
        │                                    ▲
        └──> Redis: ladder_live:<trade_date> ─┘（hash: symbol → {state, first_at, last_at, opened_at, boards_prev}；TTL 至当日 18:00）
   连续 3 轮失败 → 态置 stale=true + last_ok_ts

[GET /api/theme-mood/ladder?window=&mode=auto|live|finalized]
   auto: 交易时段且 Redis 态新鲜 → live；否则 finalized
   live   = 昨日定型梯队(断板基准) + Redis 三态 + 今日盘中列
   finalized = 现有 limit_ladder.ladder_window + 定型炸/断组（v0.5.85 即此路径 + 展示重排）
   两路径都补: 每股 candle{o,h,l,c}、每日 broken[]/blown[]、顶层 mode/as_of/stale
```

- 新模块 `src/core/limit_ladder_live.py`：TDX 扫描、三态状态机、Redis 读写、live 装配。**纯函数部分（状态机）与 IO 分离**，状态机可单测。
- `src/core/limit_ladder.py` 保持纯函数不动；定型炸/断组在其上叠加（新函数，不改旧签名）。
- Redis 键：`ladder_live:<yyyymmdd>`（hash）+ `ladder_live:<yyyymmdd>:meta`（last_ok_ts/stale/rounds_failed）。
  Redis 不可用 → live 整体降级 finalized 并在响应标注 `degraded="redis"`。

## 5. API 契约（`/theme-mood/ladder` 增量）

```jsonc
{
  "mode": "live" | "finalized",
  "as_of": "2026-09-15T14:32:11+08:00",
  "stale": false,                 // live 源中断时为 true + last_ok
  "degraded": null,               // "redis" | "tdx" | null
  "dates": ["20260911", ...],
  "ladder": [
    {
      "date": "20260911",
      "rows": [ { "boards": 3, "codes": [...], "names": [...],
                  "stocks": [ { "symbol","name","boards",
                                "candle": {"o":..,"h":..,"l":..,"c":..},
                                "pct": .., "first_time": "09:32",
                                "tag": "首板" | null } ] } ],
      "blown":  [ {"symbol","name","prev_boards"} ],   // 当日炸板
      "broken": [ {"symbol","name","prev_boards"} ]    // 当日断板(昨≥2板今未触)
    }
  ],
  "live_day": { ...同 ladder 日结构, "provisional": true } | null   // 仅 live 模式
}
```
- `rows[].stocks` 为新增逐股明细（K 线/涨幅/首封/标记）；`codes/names` 保留兼容。
- live 模式 `live_day.provisional=true`，前端据此打「盘中」角标、文案用「在板」。
- **日期格式归属**：API 的 `dates`/`date` 保持紧凑 `yyyymmdd`（与 v0.5.81 一致，不改）；
  展示成全格式 `2026-09-11` **只在前端**做（单一格式化owner，避免后端两种格式并存）。

## 6. 当日 K 线来源链（含第 0 步探针）

1. **定型日**：`klines` 日线 OHLC（现有）。
2. **盘中成形 K**：第 0 步在生产容器**只读探针** TDX `get_pricevol` 原始报文（3~5 只码，打印 keys）：
   - 含 Open/High/Low → 直接用；
   - 不含 → 退 `formula_process_mul_zb`（同 AMO 用法）取 O/H/L 公式值；
   - 再不行 → 盘中**只画实体颜色、不画影线**，并标注「盘中K不完整」。**任何情况下不编影线。**
3. 探针结论回写本文档 §6 并进 CHANGELOG 部署记录。

## 7. 前端（`frontend/src/pages/ThemeMood.tsx`）

- 页面顺序：市场情绪周期卡 → **连板梯队** → 题材表（整块折叠容器，默认展开；折叠态存 localStorage `tm-board-collapsed`）。
- 梯队列头：`fmtISO(date)` 全格式；加载/模式切换后 `scrollLeft = scrollWidth`（滚到最新）。
- 每股格子：SVG 单根 K（不引新依赖；宽 10px 高 26px，实体+上下影；绿=收<开）+ 名称 + 涨幅 + 首封时间；
  `tag=首板` 显示字样；live 列右上角「盘中」角标。
- 每日列内新增两组：`炸板 n`（红底描边）/ `断板 n`（灰底），tooltip 列「昨N板·今炸/断」全名单。
- live 模式 60s 轮询（同热力图 live 的轮询写法）；`stale=true` 时列头显示「实时源中断 HH:MM」。

## 8. 任务、错误处理、降级

- job 注册：`startup.py` 增加 `ladder_live_tick`（interval 60s、`max_instances=1`、`coalesce=True`、时段判断在任务内）。
- TDX 单轮失败：跳过本轮、保留上一轮态、`rounds_failed+1`；连续 3 轮失败 → 响应 `degraded="tdx"`，
  live 列降级为「盘中不可用，显示昨日定型」（前端按 finalized 渲染 + 横幅）。
- Redis 不可用：`degraded="redis"`，整体 finalized。
- 15:00~15:05 之间：仍 live 但标注「收盘撮合中，稍后定型」；15:05 后 auto→finalized。

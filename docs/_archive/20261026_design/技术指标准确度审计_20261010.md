## 方法

1. **静态审读**：逐文件找三类模式 —— ①当根/未来才可知的数据做当根信号（`[i+1:]`、居中窗口、
   `shift(-n)`、对"当前 bar"用当前 bar 的高/低/收做基准）; ②已发信号被后续回填改写;
   ③指标层崩溃/静默降级。
2. **机器可验的因果性针**（`tests/test_indicator_correctness.py::test_no_lookahead_*`）：
   对每个指标在 `bars[:t+1]` 上的取值，与"追加 6 根未来 K 线后重算"的历史取值逐点比对 ——
   历史取值若被改写即存在 lookahead/repaint，断言红。**全部通过**，即核心指标层的因果性
   有机器证据（不只是"人工看过没问题"）。

## 修复 1：K 线形态"相邻双底/双顶"空区间崩溃 → 整条形态链被掀翻（数据丢失）

- **证据**：`src/core/kline_pattern.py` 的 `_detect_classic_patterns`：
  ```python
  idx1 = min(range(len(bars)-20, len(bars)-10), key=...)   # 前低点下标 ∈ [n-20, n-11]
  idx2 = min(range(len(bars)-10, len(bars)),   key=...)    # 后低点下标 ∈ [n-10, n-1]
  lo, hi = min(idx1, idx2), max(idx1, idx2)
  neck = max(b.high for b in bars[lo + 1:hi])              # ← 两低点相邻(hi==lo+1)时切片为空
  ```
  当两个"相近低点"**相邻**（后低点恰好在 `n-10`、前低点在 `n-11`）时 `bars[lo+1:hi]` 为空，
  `max()`/`min()` 抛 `ValueError`。该函数**不在任何 try 内**，异常穿出 `detect_patterns`，
  被调用方 `kline_collector._detect_combined_patterns` 的宽 `except` 吞掉 → 返回 `None`
  → **该股当根的全部 K 线形态（含已识别的金针/红三兵等）一起丢失**（静默降级）。
- **复现**：`tests/test_indicator_correctness.py::test_adjacent_double_bottom_does_not_crash`
  （构造相邻双底低点，修复前 `ValueError: max() iterable argument is empty`）。
- **修复**：颈线区间为空时**跳过该形态**（不猜），不再抛异常。不改变"有颈线"情形的结果
  （`test_normal_double_bottom_still_detected` 守住）。
- **两个方向都补**：双底（`max` of high）与双顶（`min` of low）。

## 修复 2：周/月 K 线聚合把"缺失量"当 0 求和

- **证据**：`src/web/api/klines.py#_aggregate_klines`：`vol = sum(it[1].volume for it in items)`。
  同文件 `KlineData.volume` 明确允许 `None`（"P1: volume 缺失写 None, 禁止 or 0"）。
  区间内任一根 `volume=None` → `sum(...)` 抛 `TypeError`（`/klines?interval=1w` 直接 500）;
  若改用 `or 0` 又会把**无数据**伪装成**缩量**。
- **修复**：任一根缺失 → 聚合量也为 `None`（诚实口径，不伪造 0）。
- **针**：`test_aggregate_klines_none_volume_is_none` / `test_aggregate_klines_sums_when_all_present`。

## 修复 3（repaint 暴露面）：末根盘中 bar 的技术指标显式标注 `provisional`

- **问题（第 ② 类）**：`get_kline_summary`（技术面指标）若末根是**当日未收盘**的 K 线，
  MACD/KDJ/形态/量能等是**盘中值**，随最后一根 K 线走动会在收盘前被改写 —— 即"已发信号
  因后续数据回填被改写（repaint）"。GS 侧早有 `pending/confirmed` 机制，但技术指标摘要层没有。
- **修复**：新增 `kline_collector._last_bar_provisional(last_date, market)`（竞价/盘中/午休 =
  未收盘 → True; 已收盘/历史柱 → False），`get_kline_summary` 返回体加
  `provisional` + `provisional_note`。**指标数值一字未改**，只补诚实标记（前端可忽略）。
- **针**：`test_last_bar_provisional_*`（盘中 True / 午休 True / 收盘后 False / 非当日 False）、
  `test_kline_summary_carries_provisional_flag`。

## 工程 B：每日跨源标定作业

- **模块**：`src/core/indicator_calibration.py`（`daily_job` 走 jobs 框架）。
- **调度**：交易日 **16:10**（`src/bootstrap/startup.py`），与 TQ 类（15:35/15:40/15:50）及
  全市场日线（16:00）错开（TQ 背后单客户端进程）。
- **做什么**：抽样 N 只 A 股，对 **腾讯 / 东财 / TQ** 三源**当日快照**各取一次（统一归一为
  `成交量=股`、`金额=元`、`价格=元`），做两级校验：
  1. **单源恒等式** `成交量(股)×现价 ≈ 成交额(元)`（口径/容差复用 `unit_check`，实测校准 5%）;
  2. **跨源一致性**：同标的同日三源的 成交量/额/价 最大两两相对偏差 ≤ 2%（`SIDA_CALIB_CROSS_TOL_PCT` 可覆盖）。
- **不静默**：恒等式违规 / 跨源不一致 / 系统性单源缺失（整批取不到某源）→ 显式落
  `datasource_failures`（kind=`parse`/`fetch`）+ 走 `alerting.record_data_source_failure` 告警。
- **单源缺失显式降级**：仅 1 源可用的标的进 `degraded_single_source`（不补齐、不当多源结论）;
  样本内**无任一票**能做跨源校验 → `ok=False`（数据路径不完整）。
- **作业诚实性**：返回体恒带 `ok`; `ok=False` → `jobs.finish` 判 **failed**（v0.13.49 约定）。
  同类作业进行中 → 复用 `job_id` 不起第二个。
- **报告**：`DATA_DIR/reports/indicator_calibration/YYYY-MM-DD.json`。
- **与既有 `unit_recon` 的分工**：`unit_recon` 只查**单源内部**恒等式（查得出某源自己 ×10000），
  查不出**跨源**不一致；本作业补跨源这一格（快照=手/日线=股 这类"各自自洽、并排才现形"的事故）。
- **测试**：`tests/test_indicator_calibration.py`（16 例：正常/恒等式违规告警/跨源不一致/
  单源缺失显式降级/全断不可校验/系统性缺失/作业 ok=False→failed/复用活跃作业/报告落盘）。

## 〇、实施状态（2026-09-23 已完成，v0.13.0）

**阶段一已落地并在生产实测通过**（不需要专业数据包）：

| 项 | 实测 |
|---|---|
| 全A列表 | 5576 只 / 0.1s |
| 分片取日线 | 112 批（≤50/批）/ **20.64s** |
| 涨停池 | **37 只**（东财同期只有 33） |
| **连板梯队** | **4板×2 · 3板×6 · 2板×1 · 首板×28** ✅ 修掉了"恒为 1 板"的 bug |
| 最高板核对 | 大亚圣象 000910=4板 · 新华文轩 601811=4板 · 泰慕士 001234=3板 · 华远控股 600743=3板 —— 与东财 `lbc` 逐只吻合 |
| 板块 | 行业口径（通用设备/出版业/服装家纺…），概念存入独立字段 `concepts` |
| 聚合结果 | `ranked=1`（**通用设备 4 只**），其余 28 个板块 1–2 只不够门槛 |
| 客户端健康 | 小样前 / 小样后 / 全市场后 **3/3 正常** |

**踩到并修掉的坑**：TQ 源一开始把 3 个概念拼成 `theme`，而聚合的 `_resolve_group_name` 是
"theme 优先、其次 sector" ⇒ 每只票自成一个组（37 只票 → 37 组 → 全部 below_min），明明"通用设备"
有 4 只够门槛却被拆散。**概念移入 `concepts`，分组统一用行业**（与东财源口径一致）。

**专业数据包**：客户端「盘后数据下载」里**没有"专业数据"这一项**（用户实测），因此阶段二暂不可用；
但阶段一已能给出正确的连板数与板块归属，**本功能不再依赖它**。阶段二变量（首次涨停时间 / 封单额 /
板块涨停家数 / 全市场连板家数）留作后续增强，前提仍是分片 ≤50。

## 一、为什么要换（现状证据）

| 层 | 事实（生产实测） | 结论 |
|---|---|---|
| 表象 | 首页空态文案写"非交易日/涨停池为空" | **文案说错了原因**：涨停池有 33 只 |
| 直接因 | 33 只涨停散在 26 个板块（每板块最多 2 只），门槛 `MIN_LIMITUP_FOR_RANK=3` ⇒ `ranked=0` | 行情碎片化时必然空态，属正常，但**必须把原因讲对** |
| 诱因 | wudao 源当日全挂（`SSLEOFError stock.quicktiny.cn`）⇒ 降级到东财兜底，而**两源板块口径不同**（wudao=开盘啦主类题材/聚合；东财=行业板块/细分） | 同一批涨停在细分口径下散得更碎 ⇒ 更容易 0 主线 |
| 缺陷① | `market_sentiment_collector.py:176` 读 `item.get("days")`，**东财字段其实叫 `lbc`** | 连板数**恒为 1**：实测 8 只连板股全塌成首板（新华文轩 601811、大亚圣象 000910 真 4 板 → 报 1 板）⇒ 主线"高度"维度失真，龙抬头/连板梯队/情绪周期同源受害 |
| 缺陷② | 涨停池 `pagesize=60` 硬截断；东财响应自带真实总数 `tc` | 09-21 `tc=103` 只取 60（**丢 43 只**）、09-22 `tc=63` 取 60；且 `sort=fbt:asc` ⇒ **系统性丢掉尾盘涨停股**，而尾盘涨停最集中在热门板块 ⇒ 主线排名系统性偏 |

### ❌ 当前不可用（客户端专业数据包未下载/已过期，非权限问题）

```
get_gpjy_value / get_bkjy_value / get_scjy_value  →  ErrorId 10
```

这些接口一次性给出的正是最想要的东西，**恢复前提 = 在通达信客户端执行一次「盘后数据下载 → 专业数据」**：

| `GP14` / `GP22` | 涨停金额、开板次数 / 封成比、封流比 |

## 三、⚠️ 安全约束（事故教训，写进代码前必读）

**2026-09-23 实测事故**：向 17709 发**单次 5576 只 / 269 板块**的批量请求 ⇒ 客户端进入**假死态**
（整条链路 `ConnectionResetError`），生产三个端点退化（`more-info` 报"TQ 未连接"、
`/api/stocks/{s}/l2` HTTP 500、行情降级腾讯 0.1s→2.2s）。恢复链实测：`taskkill` + 计划任务
**无效** → 杀僵尸实例**无效** → **唯一解 = 整机重启**（`rebootfix.bat`，~5 分钟自愈）。
重启后另有坑：portproxy 规则在但 `172.27.16.1:17709` 不监听 ⇒ 容器超时 ⇒ 需**删了重建规则**
（**绝不要 `net stop iphlpsvc`**，它会连带停 Tailscale 切断 SSH）。

**因此本方案硬约束**：
1. **单次请求标的数 ≤ 50**，全市场必须分片循环（5576 只 = 112 次小请求，每批 ~30ms ⇒ 约 4s，可接受）；
2. 每次请求带**短超时**（≤8s）+ 重试 ≤1 次；连续失败 2 次即中止并降级，**不许压测式重试**；
3. 新代码路径**必须有分片上限的单元测试**（防回归）；
4. 盘中不得为了"探索"发大批量请求 —— 探索放收盘后，且先用 10 只验证再放大到 50。

## 四、设计

### 4.1 数据源优先级

```
TQ(新主源)  →  东财(兜底, 带 pagesize 分页修好 + lbc 映射修好)  →  wudao(可选)
```
wudao 从"优先"降为"可选"（今天全挂暴露了它是单点）；东财保留为主源的兜底并**修掉两个缺陷**。

### 4.2 池子构建（阶段一：不依赖专业包的路径，先落地）

```
① get_stock_list{market:5} → 5576 只（分片不需要, 单次 0.1s ✅）
② 分片(≤50) get_market_snapshot{codes} → Now / LastClose
   涨停判据（按板块阈值）: (Now/LastClose - 1) >= 阈值 - 容差
     主板 10% / 创业板(300,301) 20% / 科创(688,689) 20% / 北交所(4xx,8xx) 30% / ST 5%
     ⚠️ 阈值可先用 get_more_info.ZTPrice 校对少量样本；精确判据 = Now >= ZTPrice
③ 只用涨停的那几十只逐只 get_more_info → LastZTHzNum(几板) / EverZTCount(连板天) /
   FCAmo(封单额) / Ltsz(流通市值) / ZAF   ← 几十次调用, 成本可接受
④ 板块归属: get_stock_list_in_sector 扫行业(market:11)+概念(market:12) 建 股票→板块 映射
   （~360 次调用/首次, **落库缓存**, 之后每日增量）
⑤ 聚合成现有结构: {code, name, price, pct, amount, ltsz, days, sector, ...}
   days 取自 LastZTHzNum（几板）—— **修掉现在恒为 1 的 bug**
```

### 4.3 字段映射（与现有结构对接）

| 现有字段 | TQ 来源 | 备注 |
|---|---|---|
| `code` / `name` | `get_stock_list` / `get_more_info.Name` | 代码需带后缀（`002361.SZ`） |
| `price` | snapshot `Now` | |
| `pct` | `get_more_info.ZAF` 或 snapshot 自算 | |
| `days`（连板数） | **`get_more_info.LastZTHzNum`** | ✅ 修 bug 的关键 |
| `first_time` | `GP24`（专业包） | 无专业包时**缺省不填**（不编造） |
| `amount` | snapshot `Amount` | |
| `ltsz` | `get_more_info.Ltsz`（亿） | ⚠️ 单位换算需核对 |
| `sector` | `get_relation` / 板块成分映射 | |
| `封单额` | `get_more_info.FCAmo` | |

### 4.4 阶段二（专业数据包恢复后）
- `get_bkjy_value{BK12}` 直接得**每板块涨停家数** ⇒ 主线排名不必再从个股反推，口径更接近"资金在哪个板块"；
- `get_scjy_value{SC03,SC23,SC30}` 得全市场涨停/连板家数 ⇒ 可作为**交叉校验**（与池子条数对不上就是 bug）；
- `GP24` 补上**首次涨停时间**（现有 `first_time` 的语义来源）。
- 升级前提仍是**分片 ≤50** 约束。

### 4.5 顺手要修的（与本方案同批）

1. `market_sentiment_collector.py:176` `item.get("days")` → 读 `lbc`（东财源）；
2. 东财兜底按 `tc` **分页取全**（而不是 `pagesize=60` 截断）；
3. 空态文案说真话：读 `filter_stats`，写清"涨停池 N 只、分属 M 个板块，均未达 ≥3 只门槛"，**不要赖"非交易日"**；
4. wudao 源故障纳入数据源心跳（现在是静默降级，没人知道）。

## 六、风险与回滚

- **风险**：TQ 单点（今天刚挂过）⇒ 必须保留东财兜底 + 心跳告警；分片请求仍可能触发假死 ⇒ 分片上限 + 短超时 + 熔断（连续失败即降级，本轮不再试）。
- **回滚**：新源以开关控制（如 `LIMITUP_SOURCE=tq|eastmoney|auto`），出事一键切回东财；镜像回滚走既有 `panwatch-old-<tag>` 容器。
- **不做什么**：不改 `aggregate_mainline` 的门槛与打分公式（那是策略问题，先只把**输入数据修对**）；不引入新定时任务（复用现有刷新节奏）。

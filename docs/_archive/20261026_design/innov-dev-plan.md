## 发布节奏与协作约定
1. 每批次一个 feat/ 分支：pytest + 前端 tsc/build 自测 → merge --no-ff 回 main → tag → CI → 小主机重建 → 生产验证（截图/health）
2. **tag/合 main 触发生产的节点，先向老板确认节奏**（重大操作边界）
3. CHANGELOG 每 commit 必带（AGENTS.md 规范）；PG 新表过 migrations
4. 批次 B 开工前：妖股池 2.10 设计邮件补发 Hermes 对齐
5. 全部批次完成后：给 Hermes 发汇总清单邮件（做了什么/改哪些文件/测了什么/生产验证结果）

## 时间线
A（2-3 天，含周一盘中实测）→ B（2-3 天）→ C（3-5 天）→ D（2 天），合计约 **2.5 周**；A/D 独立，B→C3 有依赖。

## 二、四个系统性缺陷（跨多页复现, 按优先级）

### P0-1 固定提示条 / 警示横幅**遮挡内容**（9 页复现）

`dark-fund-top`(末行被盖) / `history`(详情被盖) / `notifications`(列表被盖) / `opportunities`(数据行被打断) /
`reports`(卡片被压) / `profile`(面板被盖) / `stocks-002361`(标题被压) / `system`(卡片被压) / `home`(文案截断)。

**根因方向**：底部"本平台数据仅供参考"这类**固定定位**的免责条 + 页内警示横幅，没有为自身高度预留空间
（内容区缺 `padding-bottom`；横幅是 `sticky/fixed` 而非文档流内块）。
**修法**：① 免责条改为**文档流内**（页面底部正常排版）或给主内容区加等高 `padding-bottom`；
② 页内警示横幅统一为流内块 + 与相邻卡片留出固定间距；③ 加一条 ui-rules 门禁：禁止 `position: fixed` 的提示条不带 `padding-bottom` 补偿。

### P0-2 图表库依赖**外部 CDN** → 国内网络/CSP 一拦就整页无图（已修，待发版）

DOM/网络探针实证：`index.html` 从 `unpkg.com` 拉 `lightweight-charts` 全局脚本（jsdelivr 兜底），
两个域都被 CSP 拦（`:: csp`），`stocks-index` 因此渲染出「图表库加载失败（网络受限时可能发生）」，
**主视觉区整块空白**（视觉分被拉到 5/10）。
**修法（已落码）**：`InteractiveKline` / `MinuteLwcChart` 的 `getLW()` 改为**优先取打包版**
（`import * as LW from 'lightweight-charts'`，该依赖本来就在 `biz-ui` 里、已进 bundle），
全局只作兜底；`index.html` 删掉 CDN `<script>`，CSP 的 `script-src`/`font-src` 收紧到 `'self'`。
→ 图表渲染**不再依赖任何外部域**。

### P1-1 空态 / 无数据时占巨幅空白（5 页）

`portfolio`(下半屏空) / `paper-trading`(两张大图空白 + 回撤曲线不可见) / `api-keys`(中部空旷) /
`shadow`(上下半空) / `heatmap`(右侧空白)。
**修法**：统一"压缩空态"——空态容器高度收敛到 `min-h-[160px]` 级、图表无数据时**不占满高**
（用 `h-[120px]` 占位 + 一行说明 + 一个主操作按钮），把省下的空间让给有数据的模块。

### P1-2 `theme-mood` 与 `heatmap` 的信息设计

- `theme-mood`（4/10）：题材×日矩阵列数过多 + 行高极小 → 纵向滚屏压力大、右侧整列空。
  **修法**：默认只显示 Top N 题材（可展开）、列数按视口自适应（隐藏最早几天）、行高提到可读下限；
  右侧空白区改成"选中题材的详情面板"（点击行 → 右侧出详情，形成主从）。
- `heatmap`（5/10）：treemap 面积按量能，单板块占半屏、小格文字截断成 `…+2…`。
  **修法**：面积做 `sqrt`/对数压缩 + 设最小可读尺寸；标签做"能放下才显示"的两级降级（全名 → 简称 → 只留色块 + tooltip）。

## 三、一致性（P2）

1. **卡片 vs hairline 混用**（admin / api-keys / opportunities / stocks-002361 / notifications 均提到）——
   与产品铁律"hairline 分隔取代边框"不一致。
   **修法**：出一版"分隔规范"（什么场景卡片、什么场景 hairline）+ 一次全站扫荡，并加 lint 规则（如禁止在列表项上同时用 `border` 与 `bg-card`）。
2. **字号层级平淡**（theme-mood / developers）→ 统一 4 级字阶（页面标题 17 / 区块 13-14 / 正文 12 / 辅助 10-11），补一处对比度检查。
3. **模态底部留白**（alerts）→ 统一 modal 内边距与主按钮权重。

## 1）Admin 后台分页

**现状实测**：`/admin` 页高 **20598px**、可见文本节点 **2958**、可点元素 **1411**（其中 **880 个 <32px**），是全站密度最高的一页。

**为什么不能只做前端**：5 个子页签（用户/邀请码/API Key/用量/Pro 审核）都是整表渲染。要"每页 20 条 + 表头固定"，需要后端 `/admin/*` 支持 `limit/offset`（或 `cursor`），否则只是把 200 条截断成"假分页"。

**要做**：
- 先查 `src/web/api/admin*` 与 `frontend/packages/api/src/*` 的现有参数，确定是加 `limit/offset` 还是前端只截前 N 条（后者必须明确写"仅显示最近 20 条"，不得冒充总数）
- 表头 `position: sticky`；小图标按钮统一 28px（**880 个 <32px 是本页主要问题**）
- 备注 placeholder「如: 给黄磊」→「如：给运营同学」（不要写死真人名）
- 「用量监控」考虑独立成二级页，而不是同页长滚

**禁区**：不改 RBAC、不改邀请码逻辑、不改 API Key 生成与校验。

## 附：L2-A 的验收线冲突（需要产品裁决）

任务书要求「首屏数字 ≤9」**同时**要求「禁止删掉任何现有数据模块」。

实测（1440×900, y<900）：
- 全展开：~120 数字 / ~239 文本块
- 只折 KPI 带 + 情绪三卡：**71 / 119**
- 再折资金流/共振/涨跌分布：**85（反而变多）**，因为下方模块顶上来
- 指数卡箭头化后：**71 / 128**

**结论**：继续折叠不会让数字变少，只有"结论层 + 证据层"保留数字、其余默认折叠才有意义。**建议把验收线改成**「首屏必须有 1 句非数字结论；数字只出现在结论层与证据层；其余模块默认折叠（localStorage 记忆）」，而不是一个凑不出来的 ≤9。

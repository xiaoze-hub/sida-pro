# SIDA-Pro UI/UX 设计指导（v1.0）

> **基线标识**：线上 `https://SIDA.hengsheng-elec.com`，版本 `v0.53.1`，仓库 commit `f1f5d83`（2026-10-24）。本文所有数字均为该基线在 **1440×900 / 1280×800** 视口下的实测值，非估计。
> **审计对象**：`frontend/src/`、`frontend/packages/`（biz-ui / base-ui）、`frontend/src/index.css`、`scripts/check_ui_rules.mjs`。代表页 5 个：`/`、`/stocks`、`/reports`、`/opportunities`、`/admin`。
> **覆盖范围**：字号 / 文字色 / 对比度 / 可点目标 / 间距 / 表面阶梯 / 交互态 / 数据态 / 动效 / 密度 / 可访问名。
> **未覆盖**：① 视觉审美（配色好不好看、留白舒不舒服）—— 需人眼判断，本轮无法自动度量（`vision_analyze` 当前 401，见 §6）；② 真实交易时段的动态态；③ 移动端真机；④ 图表内部的刻度/图例排版。
> **配套**：`20261024_UI改进_派活入口.md`（红线）、`20261024_UI全模块审计_勘误与P0任务书.md`、`20261024_剩余4项交接_Hermes.md`。

## 一、结论：当前"不够专业"不是感觉，是四项可量的物理短板

实测记分卡（v0.53.1，1440×900）：

| 页 | 可点元素 | <24px | <32px | 文本对比度抽检 | **不达标** | ≤10px 占比 | ≤11px 占比 | 无可访问名 | 输入框缺 label |
|---|---|---|---|---|---|---|---|---|---|
| `/` 首页 | 84 | 8 | 48 | 351 | **57 (16%)** | 33% | 67% | 0 | 0 |
| `/stocks` 持仓 | 58 | 5 | 20 | 110 | **29 (26%)** | 30% | 55% | 6 | 0 |
| `/reports` 报告中心 | 106 | 10 | 20 | 272 | **22 (8%)** | 23% | 66% | 0 | 0 |
| `/opportunities` 机会 | 105 | **43 (41%)** | 58 | 274 | **36 (13%)** | 14% | 35% | **30** | 0 |
| `/admin` 管理后台 | 185 | 6 | **148 (80%)** | 1112 | **312 (28%)** | 15% | 27% | 16 | **31 / 34** |

四项硬短板，按"用户能不能感觉到"排序：

### 1. 文字用透明度降层级 → 实测 2.22:1（AA 需 4.5）
全站 **313 处** `text-*/NN`。暗色次级色本身是 **4.92:1**（刚好过线），叠 70% alpha 后掉到 **2.22:1** —— 侧栏分组标「行情 / 机会 / 决策」就是这么灰的。**它在肉眼上只像"稍微淡一点"，不会有人报 bug，但会整体让人觉得"发虚、不清晰"。** 这是最大单一来源。

> **已修（本文同批）**：313 处全部改实色；新增 lint 规则 **R14-TEXT-ALPHA**（带 0 基线，禁止再出现）。

### 2. 可点目标过小 → `/admin` 80% < 32px、`/opportunities` 41% < 24px
WCAG 2.2 AA 的底线是 **24×24 CSS px**；桌面端图标按钮的舒适值是 **28px**。后台 148 个 <32px 的按钮意味着**每个都要瞄一下才能点中**，这是"专业工具"和"网页"的分界线。

### 3. 可访问名缺失 → `/opportunities` 30 个、`/admin` 16 个
纯图标按钮没有 `aria-label`/`title`，读屏器读作"按钮"，键盘用户也看不到提示。`/admin` 另有 **31/34 个输入框没有关联 label**（只靠 placeholder）—— placeholder 一输入就消失，错误信息也无处挂靠。

### 4. 字号过小 → ≤11px 占 55–67%
10px 是合法档位（用于次要标注/密集列），但**占比 33% 意味着"次要"变成了"主体"**。专业金融终端确实密，但密度应来自"信息排布"，不是"把字缩小"。

## 二、六条设计原则（交易终端专用，不是通用 UI 套话）

1. **结论先行，证据可折**。一屏必须能独立回答"今天怎么打"。折叠不是藏 —— **折叠块的表头必须自带结论**（实测反例：v0.53.0 把情绪卡收起后，用户不知道"为什么"，白折）。
2. **看图决策，不做数据堆砌**。K 线/分时是绝对主角（≥80% 屏宽、无卡片包裹）；其余模块用卡片托底（卡片化已翻案，见 §3.6）。
3. **每个数字都要有出处与口径**。四档资金结构（`tdx_exday4` / `eastmoney4` / `ths` / `tick`）**不可换算**，同屏必须各带标签；档位阈值标注"推断值"。
4. **缺数据要显式，不能拿 0 冒充**。`--` + 原因 + 下一个动作；`null` 与 `0` 在 UI 上必须可区分（有测试钉死）。
5. **层级用尺寸/字体/表面，不用透明度**。alpha 调色在小字号上等于自杀（§1.1 实测证据）。
6. **动效服务于状态变化，不服务于"高级感"**。只动 `transform`/`opacity`，150–200ms，必须 respect `prefers-reduced-motion`（当前**已支持**，实测 CSS 命中）。

## 三、规格（可直接照抄，含判据）

### 3.1 字号阶梯：只有 4 档

| 档 | 值 | 用途 | 禁止 |
|---|---|---|---|
| 标注 | **10px** | 图表轴标签、密集表格的次级列、`title` 提示 | ❌ 承载结论数字 ❌ 可点元素 ❌ 首屏主信息 |
| 正文 | **12px** | 表体、列表项、控件标签 | ❌ 低于 11px |
| 强调 | **13px** | 区块标题、关键读数 | — |
| 结论 | **16px** | 一句话结论、情绪阶段名 | — |
| 大数 | **20px** | KPI 主数字、指数点位 | — |

判据：`text-[10px]` 占比 > 40% 视为失控（当前首页 33%，需继续收敛）；`text-[9px]` 及以下 **0 容忍**（已有 R10 棘轮）。

### 3.2 文字色：只有 2 档实色，第三档用字号/字重

| 档 | Token | 暗色实测（对卡片 13.5%） | 用途 |
|---|---|---|---|
| 主 | `text-foreground` | ≥ 12:1 | 结论、数字、标题 |
| 次 | `text-muted-foreground`（`--muted-foreground: 240 10% 58%`） | **4.92:1** | 标签、单位、来源、口径 |
| 更弱 | **不是颜色** —— `text-[10px]` + `font-normal` | 继承 4.92:1 | 角标、辅助说明 |

**禁止**：`text-muted-foreground/70`、`text-foreground/80` 这类写法（R14 拦截）。**有色底上的 alpha**（`text-primary/70`、`text-white/90`）不在禁止内，但需实测其对比度 ≥3:1。

硬底线：**任何可见文字对实际背景 ≥4.5:1**（大字 ≥3:1）。当前残留不达标 57/29/22/36/312 条，主要是语义色块（涨跌/评分）与禁用态，需逐条判定是"设计允许"还是"缺陷"。

### 3.3 语义色预算：一屏 ≤5 种

涨红、跌绿、警示琥珀、强调紫（仅交互）、中性灰。**同一含义只能一种颜色**（历史上「机会页止损」与「目标」同为红色，读者无法区分）。

涨跌色铁律：**买红卖绿**（国内惯例），且 **Hex / HSL 三元组 / 测试字面量三处必须同步**改（只改 Hex 会让闪烁动画闪旧色）。

### 3.4 可点目标

| 场景 | 最小 | 备注 |
|---|---|---|
| 桌面图标按钮 | **28×28** | `h-7 w-7`；工具栏可 24，但必须有 `title` |
| 桌面文字按钮 | **28 高** | 宽度随文案，内边距 ≥8 |
| 移动触控 | **44×44** | 底部导航、列表行 |
| 行内小链接 | 24×24 | 需扩大点击区（`py-1 -my-1`） |

现状：`/admin` 80% <32px、`/opportunities` 41% <24px。**整改顺序**：先 `/admin` 表格操作列（最密），再 `/opportunities` 卡片内图标。

### 3.5 间距：4 的倍数，6 档

`4 / 8 / 12 / 16 / 24 / 32`。禁止 5、7、9、11、13、15、18、20、22 这类"看起来差不多"的值（会产生肉眼可辨的不齐）。区块之间 ≥16，区块内 ≤12，卡片内边距 12–16。

### 3.6 表面阶梯：判据是 ΔL，不是 WCAG

| 层 | 暗色 HSL | 说明 |
|---|---|---|
| 页底 | `240 20% 5%` | |
| 卡片 | `240 18% 13.5%` | **ΔL = 8.5 个点**（≥8 才看得出"有底"） |
| hover | `240 18% 17%` | ΔL +3.5 |
| 浮层 | `240 16% 21%` | 下拉/弹层，必须明显高于卡片 |
| 卡片边框 | `--border-strong: 240 17% 27.5%` | 对卡片 **1.53:1**（≥1.5） |

**为什么不用 WCAG 判层级**：近黑区间 `(L+0.05)` 项把差异压平，`#0b0b12` vs `#15151f` 实测只算出 1.08:1，但人眼能看出差别。**表面分离用 ΔL ≥8%，边框仍用 WCAG ≥1.5:1。**

卡片化口径（2026-10-24 翻案）：**只有 K 线/分时画布不包卡片**；其余数据模块恢复卡片；卡片内不套卡片，同屏嵌套 ≤2 层。

### 3.7 交互六态：一个都不能少

| 态 | 要求 |
|---|---|
| default | — |
| hover | 背景提一档（`bg-s2`）或边框提亮，**不允许只改鼠标指针** |
| focus-visible | **2px 外环**（`:focus-visible` 全局已配），键盘可达的每个可操作控件都要有 |
| active | 轻微下沉或加深，不可无反馈 |
| disabled | 降透明 + `cursor-not-allowed`，且**保留可读**（≥3:1） |
| loading | 按钮内替换为 spinner + 禁用（**防重复提交**） |

实测：全局 `:focus-visible` 已覆盖；`/opportunities` 有 30 个可交互元素无可访问名，属 §1.3 待补。

### 3.8 数据四态：禁止裸 `--`

| 态 | 必须包含 |
|---|---|
| loading | 骨架屏或"加载中…"，**不得渲染成"共 0 只"**（2026-10 竞价页事故） |
| empty | 原因（休市/无权限/源不可用）+ 何时有数据 + 一个可点动作 |
| error | 错误源名称 + 重试入口（`ErrorBanner` / 行内重试） |
| stale | 数据日 + 滞后年龄（过期数据 + 标注 > 空白） |

`null` 渲染为 `--` 且带 `title` 说明；**`0` 与"无数据"在代码与 UI 上都不可混**（有测试钉死）。

### 3.9 动效

- 时长：状态切换 **150ms**，展开/收起 **200ms**，超过 300ms 视为迟钝。
- 属性：只动 `transform` / `opacity`（GPU 友好）；不动 `width/height/top/left`。
- 必须 `@media (prefers-reduced-motion: reduce)` 降级（已支持）。
- 同屏同时动画 ≤3 处，否则是"花"。

### 3.10 密度三档（已存在于 `:root[data-density]`）

`compact 3px 基准` / `normal 6px` / `comfortable 8px`。密度只改间距，**不改字号**（改字号会造成同一页面两种排版语言）。

## 六、明确不做（避免过度设计）

- **不引入 Bento 网格 / 阴影分层 / 大面积渐变**：与"看图决策"冲突，也会撞 R12/R13。
- **不换绿涨红跌**：国内惯例已定，改了全站语义要重训用户。
- **不把所有 10px 提到 12px**：密集表格列、图表轴标签提到 12px 会撑破布局，收益为负。
- **不为"美观"加装饰性插画/圆角/彩色卡片**：这是终端不是官网。
- **不在本轮追求 WCAG 全量 AAA**：先做到 AA 的 4.5:1 与 24px 目标，收益最大。

## 七、关于 `nextlevelbuilder/ui-ux-pro-max-skill`（139.7k stars）

**结论：取它的"规则清单"，不取它的"视觉默认值"。**

- **可取**：`.claude/skills/ui-ux-pro-max/data/ux-guidelines.csv` —— **119 条 UX 规则**（Category / Issue / Do / Don't / Severity，其中 Critical 4 条、High 44 条）。它是**厂商中立的可审计清单**，与平台/框架无关，本文 §3.7–3.9 的分类就参照了它的 Accessibility / Interaction / Feedback / Animation 分组。
- **不取**：它的 `styles.csv` / `colors.csv` / `typography.csv` 提供的视觉默认值（Bento 网格、阴影分层、常规字阶、绿涨红跌）——与本仓铁律和 `check_ui_rules.mjs`（R6/R10/R12/R13）**直接冲突**。
- **不整仓安装**：本机已有 `design`（同源 CSV 检索）+ `sida-pro-design-system` 等 7 个更专的技能；缺的不是设计灵感，是**把规则变成门禁**。本文 §4 的 R14 就是这条路线：从"建议"变"改坏即红"。

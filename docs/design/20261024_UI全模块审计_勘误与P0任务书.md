## §7 勘误（3 条必须先处理）

### 🔴 7.1 G1「最小字号 ≥12px」与本项目产品铁律**直接冲突，不得照做**

正文 G1 要求：全站最小字号 ≥12px，`10px` 仅允许用于滚动快讯与图表轴。

**铁律原文**（`docs/design/20261023_01_design_tokens.md:473`）：
> 字号只用 10/11/12/13/16/20 ｜ `--fs-*` 六档，无第七档

即 **10px 是合法档位**，且已有 `--fs-10 … --fs-20` token 体系。照 G1 全站拔到 12px 等于推翻铁律、并触碰 461+ 处任意值。

**替代方案（待产品裁决，默认按此执行）**：
- 保留 10px 合法；
- 但**限制其用途**：10px 只允许做「次要标注 / 密集表格列 / 图表轴」；
- **禁止** 10px 承载：结论数字、关键指标值、可点元素文案、错误提示。
- 验收改为：**首屏结论区最小 ≥13px，关键数字 ≥20px**；全站 `text-[10px]` 只增不减（用 R6/R12 棘轮同法锁死）。

### 🔴 7.2 G4 建议的边框色 `#2b2b3f` **达不到验收标准 §6.3 的 ≥1.5:1**

实测（WCAG 相对亮度法，卡片底 `#15151f`）：

| 边框色 | 对比度 | 是否达标 |
|---|---|---|
| `#2b2b3f`（正文建议值） | **1.31:1** | ❌ |
| `#333348` | 1.47:1 | ❌（差一点） |
| **`#3a3a52`** | **1.65:1** | ✅ 建议改用此值 |
| `#40405c` | 1.82:1 | ✅（更稳） |

另：正文称「边框 `#2b2b3f`（≥1.5:1）」是**计算错误**，请按其修复方案实施时以本表为准。

### 🔴 7.3 G3 改涨红**必须三处同步**，否则涨跌闪烁动画会变双色

现状（`frontend/src/index.css:27 / :151`）：

```css
--stock-up: #E53935;
--stock-up-hsl: 1.364 77.193% 55.294%;   /* 由上面 Hex 换算而来 */
```

闪烁关键帧用的是 `hsl(var(--stock-up-hsl) / var(--flash-alpha))`，并且有两条钉子：

- `frontend/tests/components/stock-flash-token.test.ts:107`
  → `expect(DECLS.get('--stock-up')).toEqual(['#E53935', '#E53935'])`（亮/暗两套）
- 同文件 `:122` → hex 与 HSL 三元组必须同色

**只改 Hex 不改三元组的后果**：文字/柱体是新红，闪烁底色仍旧红 —— 这正是 `v0.49.0` 修掉的「非法 CSS 静默失效」的同类问题，只是更隐蔽（会闪，但闪错色）。

**正确改法（三处一起）**：
1. `--stock-up: #ff5252`（两处：`:root` 与 `.dark`）
2. `--stock-up-hsl: 0 100% 66.1%`（对应 `#ff5252`；必须用精确换算，不是估）
3. `stock-flash-token.test.ts` 里的 `#E53935` 字面量改 `#FF5252`
4. **跑** `npx vitest run tests/components/stock-flash-token.test.ts` 确认 6 条仍绿

> 顺带：正文称 `#ff5252` = 5.63:1，实测 vs 卡片 `#15151f` 为 **5.68:1**、vs 页底 `#0a0a0f` 为 **6.19:1**，结论不变（达标）。

### 7.4 G1 的数字口径要修正

- 正文：首页「581 个节点，10px 266 个（46%）」
- 实测（只统计**有文本的叶子节点**，1440×900）：**1268 个**，`10px` 435（**34%**）、`11px` 383（30%）、`12px` 338（27%）、`13px` 86（7%）、`16px` 17（1%）、`20px` 9（1%）
- **结论方向一致（≤12px 占 91%），但 46% 偏高**。任务书里请引用 34%，否则会被怀疑漏计节点。

### Lane B｜G9 弹窗跨路由残留（P0 功能性 bug）

- **文件**：`frontend/src/pages/PriceAlerts.tsx`、`frontend/src/App.tsx`（路由层）
- **问题（已实测）**：进入 `/notifications?tab=alerts` 即弹出「新建提醒规则」且预填「中粮糖业 (600737)」；切到 `/admin` 后该 dialog **仍在**，遮罩盖住整页
- **要求**：
  1. **先定位 auto-open 触发点**（推测与 `prefillDone` / `formOpen` 有关，文件里 `useState(false)` 不是唯一入口），把触发条件改成「仅用户显式点击『新建规则』」
  2. 路由切换统一关闭所有 `role="dialog"`（在路由层 `useEffect` 里 closeAll；Dialog 挂到路由子树而非全局 portal）
  3. 顺手：`push` 渠道枚举改中文「系统推送」
- **验收**：自动化断言 —— 进入 alerts 页后 `document.querySelectorAll('[role="dialog"]').length === 0`；点「新建」后 =1；切 `/admin` 后 =0
- **测试**：新增 `frontend/tests/components/price-alert-dialog-route.test.tsx`，锁死上述三步

### Lane C｜F3 模拟盘 Y 轴刻度（真 bug）

- **文件**：`frontend/src/pages/PaperTrading.tsx`
- **问题（已实测）**：曲线区 SVG 内 5 个刻度文本全为 `100.0万`（0 收益时 min==max 导致刻度退化）
- **要求**：
  1. 轴刻度生成加**对称 padding**：`min/max` 相等或跨度 <1% 时，按 `值 ± max(|值|*0.01, 1000)` 撑开
  2. 刻度格式化后**去重**，至少保留 2 个不同值
  3. 0 收益曲线改中性灰（不用涨红）
  4. 回撤曲线独立分节（hairline），不裁切
- **验收**：断言刻度文本数组 `new Set(ticks).size >= 2`；给一个 0 收益 fixture 的单测
- **禁止**：不改收益计算逻辑

### Lane D｜C4 战报与暗盘内容重复（P0 内容重复）

- **文件**：`frontend/src/pages/WarReport.tsx`、`frontend/src/pages/DarkFundTop.tsx`（先定位两页共用的表格组件，**只改战报侧**，别动暗盘）
- **问题（已实测）**：两页首屏是同一张表同一批 20 行
- **要求**：
  1. 战报首屏改为**结论层**：今日主力净流入方向 + 最集中的 3 个行业 + 最异常的 3 只票（数据若已有则直接用，缺则显式「无数据（原因）」，**禁止现算编造**）

### Lane E｜C1 机会页 8 张 KPI 把结果表挤出首屏（P0）

# 盘前报告 → 盘前分析 Agent：改造设计（2026-10-23）

> 用户裁决：**「盘前报告不如盘前分析实用」**，要求把「盘前报告」升级为「盘前分析 Agent」。
> 本文件是派活依据：文件级归属、验收命令、不做清单都写死，子智能体按段领任务。

## 0. 现状（实测，不是推测）

生产库与服务端实测（2026-10-23）：

| 产物 | 生成者 | 时间 | 数据 | 是否按用户 |
|---|---|---|---|---|
| `premarket-daily`（A股盘前报告） | `src/core/report_generator.py` 模板拼装 | 08:30 | 隔夜外盘、涨停梯队、快讯、候选/持仓 | **否**，全站同一份 |
| `premarket_outlook`（盘前分析） | LLM Agent，落 `analysis_history` | 09:05 | 大盘四碗面门禁、主线、事件驱动、持仓预案 | **是**，按 `user_id` |

实测证据：

- `/api/reports/list` → `premarket-daily` 2 个 job（`premarket-daily` / `postmarket-review`），最新 `2026-10-23_08-30-39.md`；
- `/api/history?kind=workflow` → `premarket_outlook` 107 条、`daily_report` 104 条，最新 `2026-10-23 09:12`；
- 两篇正文风格完全不同：报告是**纯数据表格**（`Generated By: SIDA 内置报告生成器`），分析是**带门禁结论的研判**（环境分/仓位上限/证伪条件）。

**结论**：不是「报告差」，而是**两者应该合体**——报告的确定性证据（隔夜外盘、涨停梯队结构、快讯热度）正是分析 Agent 现在最弱的一环（它常写「涨停 5580 家（数据异常）」这类脏数据结论）；而分析 Agent 的研判、持仓预案、证伪条件正是报告永远给不出的。

## 1. 目标与非目标

### 目标（按用户口径）

1. **入口扶正**：全站「盘前」默认指向**盘前分析 Agent**，静态报告降级为「分析底稿/归档」。
2. **证据合流**：报告生成器的确定性数据作为 **证据源**喂给分析 Agent，消灭「数据异常」这类脏结论。
3. **闭环可用**：首页/分析页可「立即分析」，跑完可「问参谋」继续推演，并能把关键位落到 K 线上。

### 非目标（明确不做）

- ❌ **不做大盘涨跌方向预测**。铁律：方向交用户，Agent 只做情报备料 + 关键位 + 应对剧本。
- ❌ 不删除 `report_generator.py`（它对盘后、推送、历史归档仍有价值，本次只改**定位与消费方式**）。
- ❌ 不动 `premarket_strategist` 配方的 Frozen Ring（`symbol_guard` / `number_audit` / `caliber.py` / 交易 403 / TQ 优先链 / `SYSTEM_PROMPT` 约束段）。
- ❌ 不改 `src/web/api/chat.py`（2307/2310 行护栏，只允许集成方加 import）。
- ❌ 不做新的 K 线图组件；复用现有 `price-anchors` + 图表标注能力。

## 2. 架构：三段式

```
        ┌───────────────────────────── 08:30 ─────────────────────────────┐
        │ report_generator.collect()  →  PremarketEvidence（结构化证据）    │
        │   · overnight：外盘/亚太/大宗/汇率                                │
        │   · ladder：涨停家数/连板梯队/板块分布（带失真标记）               │
        │   · news：快讯按主题聚类 + 热度                                   │
        │   · user：持仓/自选（按 user_id）                                 │
        └───────────────────────────────┬─────────────────────────────────┘
                                        │  证据（可复用、可落库、可审计）
        ┌───────────────────────────────▼─────────────────────────────────┐
        │ 09:05  premarket_outlook（盘前分析 Agent）                        │
        │   system: 不做方向预测；缺失维度写「未取到（原因）」               │
        │   user  : 证据块 + 我的持仓/自选 + 昨日复盘结论                    │
        │   产出  : 环境门禁 / 主线 / 事件驱动表 / 逐票预案 / 证伪条件       │
        │           → analysis_history（含 structured_payload）             │
        └───────────────────────────────┬─────────────────────────────────┘
                                        │  structured_payload
        ┌───────────────────────────────▼─────────────────────────────────┐
        │ 数智参谋 @盘前策略官                                              │
        │   自动注入「今日盘前分析底稿」→ 可追问、可画线、可存预案           │
        └─────────────────────────────────────────────────────────────────┘
```

**关键设计决策**

1. **证据层单独成模块** `src/core/premarket_evidence.py`：纯取数 + 纯结构化，不调 LLM、不写盘。
   - 为什么不是直接复用 `report_generator.collect()`：它把「取数 / 拼模板 / 写盘 / 推送」耦在一个函数里，无法在 Agent 里复用。
   - `report_generator` 改为**调用**证据层，两边共用同一份事实，从根上消除「报告与分析数字不一致」。
2. **结构化产出**：`premarket_outlook` 除正文外，落一份 `structured_payload`（门禁分/仓位上限/主线/逐票预案/关键位），供参谋注入与前端渲染，而不是让前端去正则解析 Markdown。
3. **脏数据必须显式标注**：证据层给每个字段带 `quality`（`ok` / `suspect` / `missing`）+ `reason`。涨停 5580 家这类异常由**取数层**判定，不许把判断权丢给 LLM。

## 3. 三支并行（文件不相交，可同时开工）

### A 支线 · 后端证据层（`feat/premarket-evidence-1023`）

**负责人**：子智能体 A ｜ **依赖**：无（可最先开工）

**必改文件**

- `src/core/premarket_evidence.py`（新建，~300 行）
  - `collect(date, db, user_id=None) -> PremarketEvidence`
  - 数据块：`overnight` / `ladder` / `news` / `sentiment` / `watchlist` / `portfolio`
  - 每块：`{ "items": [...], "quality": "ok|suspect|missing", "reason": str, "source": str, "as_of": iso }`
  - 失真判定（写死在取数层）：涨停家数 > 全市场股票数、连板高度与家数矛盾、快讯全为同一时间戳 → `suspect`
  - **必须**：纯函数式取数，失败块 `missing` + 原因，**绝不抛**；不写文件、不调 LLM
- `src/core/report_generator.py`（改）
  - `collect()` 内联取数改为调用 `premarket_evidence.collect()`；模板渲染逻辑保持不变（**输出格式不改一字**，避免破坏推送与历史）
  - 顺带吃掉 bug：`_build_template_report` 里直接信任涨停家数，改为按 `quality` 打 `⚠️ 数据待核` 角标
- `tests/test_premarket_evidence.py`（新建，≥8 例）
  - 失真判定（涨停家数超上限 / 连板矛盾）、缺失块不抛、`report_generator` 输出与旧版逐字节一致（用固定 fixture 断言）

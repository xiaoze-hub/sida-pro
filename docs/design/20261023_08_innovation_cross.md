# 跨模块深度联动创新方向（v0.48.0）

- **基线**：`v0.48.0 / 5427af0`（分支 `docs/design-8`）
- **文档定位**：本文不是新功能清单，而是「把已经落库、已经跑通、但彼此不通电的模块接起来」的 5 条化学反应路径。每条路径都给出可验收的落地线与明确的「不做项」。
- **覆盖范围**：

  - ⚠️ **设想，需先行验证**：方案 1 的「形态点 → 预测锥形包络」映射规则、方案 3 的「事件强度 × 竞价抢筹匹配度」共振公式、方案 5 的「自然语言 → 通达信公式」编译器，均为设计设想，**尚无代码**，验收线里已写明必须先跑离线样本再谈上屏。
  - ❗ **待裁决的一致性缺口**：`-8%` 止损在 `DefenseLineBanner.tsx:65`（`cost*0.92`）、`intraday_monitor.py:1889`（`<=-0.08`）、`paper_trading_engine.py:50`（`0.92`）三处硬编码，与 `scenario_cost_anchor.py:11` 明示的「绝不默认 -5%/-8%」直接冲突。本文方案 2 依赖这条线，**但在裁决前只做「展示合规度」，不做「拦截下单」**。

- **不做**：任何形式的「大盘涨跌方向预测」。所有胜率类结论必须同屏给出「样本数 + 同池无条件基准 + 是否剔除 T+1 一字涨停」，缺一项即降级为「观察值」不得称能力。

## 方案 1：威科夫形态（Spring / LPS）× Kronos 时序沙盒 —— 形态点 → 预测锥形包络 + 关键止损位

### ① 跨模块化学反应

今天这三块是三条平行线：

1. `src/core/wyckoff.py` 的 `analyze_wyckoff(bars, lookback=60)` 已经产出定量的形态标记（`_m_spring_probe` 弹簧试探、`_m_dry_up` 缩量、`_m_markup_break` 突破、`_m_effort_divergence` 量价背离），并给出 `_verdict()` 的 A/B/C/D 阶段判定——**但结论是文字**，`WyckoffMark` 只有点位没有概率，用户看完不知道「这个 Spring 值不值得等」。
2. `forecast_server.py:/predict` 已经能返回 kronos / chronos / xgboost / linreg / timesfm 五路预测与加权中位数，`/forecast/card` 还能出卡片——**但它不知道当下正处于 Spring 试探点**，预测是无条件的，等同于「对任何一天都说同样的话」。
3. `KlineChart.tsx` 的 `KlineSubchart` 已有 6 档副图位，**但副图是「指标」语义，不能承载「事件锚点 + 概率带」**。

化学反应点：**用威科夫标记给 Kronos 的预测分布做条件切片**。Spring/LPS 确认日的历史切片里，未来 N 日收益分布天然是双峰的（成功回收 vs 破位），单一加权中位数会把这个双峰平均成一个没意义的数。所以不是「预测涨跌」，而是**把条件分布画成锥形**：中位线 + 25/75 分位 + 5/95 分位，叠加形态点自身的失效线（Spring 低点下方 1 个 ATR%），让用户看到「上沿空间 / 下沿代价 / 需要多久」。

纪律边界：锥形包络**只描述条件分布形态，不输出方向结论**，文案固定为「同类形态历史分布」，不写「看涨/看跌」。

### ② 新增 UI 组件与按钮

- **`WyckoffConeOverlay`**（新增，挂在 `KlineChart.tsx` 主图层，不使用卡片边框，用 hairline 描边 + 半透明填充）：形态点 → 预测锥形。锥形 4 条带（5/25/75/95 分位），当前价水平虚线 1px，形态失效线用警示色虚线（确切色值遵设计令牌，不手写十六进制），`tabular-nums` 标注宽度、天数。
- **`KlineSubchart` 第 7 档 `wyckoff`**：柱状显示「Spring 试探量能 / 缩量比」，与既有 6 档同级，不新增 Tab，避免破坏 6 档布局密度。
- **`StockWorkbench` 右上「形态沙盒」按钮**（次级按钮，非主按钮）：点击展开右侧浮条（唯一允许 `.shadow-float` 的场景，因为它是框选即问浮条），显示：形态名 / 阶段 / 样本数 / 同池基准 / 是否剔除一字板 / 锥形口径说明。无数据时该按钮置灰并 tooltip「同类样本不足 30，不出锥形」。
- **字号纪律**：标题 13、数值 12、说明 10；金额单位「亿/万」；涨红跌绿。

### ③ 后端实现路径

1. `src/core/wyckoff.py`：`WyckoffMark` 增加 `anchor_px`（形态关键点）、`invalid_px`（失效线）、`atr_pct`，不改既有判定逻辑（Frozen 之外，可改）。
2. 新模块 `src/core/wyckoff_cone.py`：
   - `build_cone(symbol, mark, days)` → 调 `backtest_lab.evaluate_bars_universe` 的同口径前瞻函数 `_forward_outcome`，但**入样条件换成「同类 mark 出现日」**，产出分位带；
   - `_is_untradable_next_bar` 复用既有剔除一字板逻辑（已有，别重写）；
   - 输出结构固定含 `samples / baseline_same_pool / excluded_limit_up / buckets`，**缺 baseline 直接抛错，不降级**。
3. `forecast_server.py` 新增 `GET /predict/cone?symbol=&mark_type=&days=`：只读，不触发新训练；数据不足返回 `409` + `reason`，前端据此置灰。
4. 交叉验证：锥形中位线 vs `/predict` 加权中位线同屏并列，**两条都保留**，差异 > 阈值时打「两口径分歧」标签，不融合成一条（融合会掩盖分歧，等于造假）。

### ④ 数据前提

- 需要**足够长的日线史**才能切出 ≥30 个同类形态样本：`evaluate_bars_universe` 默认 `limit_symbols=400, lookback_days=450`，Spring 这类形态出现频率低，450 天 × 400 只大概率不够。**这是本方案最大风险，必须先跑一次离线计数确认**，未确认前不上屏。
- `invalid_px` 依赖 ATR%，需要 `exday_daily` 的波动字段或自行从 K 线算（可算，无外部依赖）。
- 不依赖 Kronos 在线可用性：`/predict` 已有 `kronos_ready=false` 的诚实降级路径（`forecast_server.py:104`），锥形在 kronos 缺失时改用 chronos 单模型并在 UI 标注，**不许静默混用**。

### ⑤ 分阶段落地与验收线

- **P0（1 周）离线计数**：写一个只读脚本统计全市场 Spring/LPS 样本量，产出「按年 × 按形态」的样本表。**验收线：任一形态在最近 3 年内样本 ≥30 的股票占比 ≥20%，否则本方案降级为「仅自选股可用」。**
- **P1（1 周）锥形接口**：`/predict/cone` 上线，返回四带 + baseline + 剔除标记。**验收线：单票响应 <1.5s；样本 <30 时返回 409；单测覆盖「缺 baseline 必须抛错」。**
- **P2（1 周）前端叠加**：`WyckoffConeOverlay` 上屏。**验收线：K 线区占比仍 ≥80% 屏宽；锥形关闭时无 layout shift；1024px 宽下不遮挡价格轴。**

### ⑥ 风险与不做项

- **不做**：不用锥形给「买/卖」字样；不做「形态胜率排行榜」（样本稀薄，排行即误导）。
- **风险**：形态条件切片本质是**样本内过拟合的温床**。缓解：锥形只允许在全市场横截面样本上算，**禁止按单票自身历史算**（单票几十个样本的分位数毫无统计意义）。
- **风险**：`wyckoff.py` 的 Spring 判定本身带「须次日缩量企稳(LPS)才确认」（源码注释即如此），意味着**确认时点滞后一天**，锥形的起点必须标「确认日」而非「试探日」，否则回测虚高。

## 方案 2：决策账本 × 影子账户 `-8%` 硬防线 × AI 纪律审计 —— 下单/持仓时弹「三层滤网合规度 + 历史同类操作胜率」

### ① 跨模块化学反应

三块现状：

- `DecisionLedger.tsx` 记录「我做了什么决定」，是**事后账本**；
- `ShadowHub.tsx` + `paper_trading_engine.py` 跑影子账户，`paper_trading_engine.py:50` 硬编码 `0.92`（即 -8%）作为止损；
- `DefenseLineBanner.tsx:65` 用 `cost*0.92` 画防线，`intraday_monitor.py:1889` 用 `<=-0.08` 触发告警。

**它们互相不知道对方存在**：账本不知道这笔操作违反了自己过去的纪律；影子账户不知道真实账户在同一标的上已经违规过一次；防线只在价格跌破时说话，从不在「下单那一刻」说话。

化学反应点：把「纪律」从**事后复盘**前移成**下单时的合规度读数**。用户在 `DecisionLedger` 或 `PaperTrading` 提交一笔操作时，同屏给三件事：

1. **三层滤网合规度**（口径来自 `docs/_archive/20261026_design/本土三层滤网_设计_20261016.md`）：逐层打勾/打叉，给出「本次操作命中/违反了哪一层」，**只报事实不给分数**（合成分数会诱导用户刷分）。
2. **历史同类操作胜率**：从账本自身历史里按「同标的池 × 同操作类型 × 同市况」切片，必须带样本数 + 同池无条件基准 + 是否剔除一字板。
3. **当前防线状态**：现价距 `-8%` 线的百分比距离（读 `DefenseLineBanner` 同一口径），不做预测。

❗ **待裁决点（必须在此标明）**：`-8%` 与 `scenario_cost_anchor.py:11`「绝不默认 -5%/-8%」冲突。因此本方案第一期**只展示、不拦截**：弹层显示「当前系统按 -8% 计算，但成本锚定模块声明不设默认阈值，口径待裁决」，并提供「按我的实际成本重算」入口。**裁决前严禁把 -8% 写成产品规则，也严禁新增第四处硬编码。**

### ② 新增 UI 组件与按钮

- **`DisciplineAuditSheet`**（新增，右侧抽屉，非卡片）：三段式（合规度 / 同类胜率 / 防线距离），每段之间用 hairline 分隔，**不用卡片边框**。
- **`DecisionLedger` 行内「审计」按钮**：对这个按钮的每一历史决策重跑一次审计，输出「当时若审计会给出什么」，用于校准审计本身是否有信息量。
- **`PaperTrading` 下单浮条前置勾选**：唯一允许 `.shadow-float` 的位置（框选即问浮条语义），显示一行 `合规 3/3 · 同类 42 笔 胜率 38% (基准 31%, 已剔一字板)`，字号 11，`tabular-nums`。
- 红绿纪律：否决/违规提示用买入红以外的警示色，**不得用绿色表示「通过」在下跌场景中造成歧义**——通过态用中性灰勾。

### ③ 后端实现路径

1. 新模块 `src/core/discipline_audit.py`：
   - `audit_order(symbol, action, price, size, ctx)` → `{filters:[{layer,pass,reason}], similar:{n,winrate,baseline,excluded}, defense:{cost,line_pct,distance_pct,source}}`
   - `similar_ops()` 走账本表 + `factor_winrate_daily` 的既有聚合口径（`backtest_lab.load_winrates`），**不新造胜率算法**。
2. 防线口径统一：抽 `defense_line(cost, *, profile)` 单一函数到 `src/core/scenario_cost_anchor.py` 的邻位（**不改 `caliber.py`，Frozen**），三个硬编码点改为调用它，`profile` 由裁决结果决定，默认值保持现状以免线上行为跳变。**该函数需人工批准后才允许替换 `intraday_monitor.py:1889`。**
3. API：`POST /discipline/audit`（只读计算，不落单）、`GET /discipline/audit/history?decision_id=`。
4. 与 AI 的关系：AI 只做**归因叙述**（把三段结构化读数写成一句人话），**不参与是否放行的判定**，判定必须可复算。

### ④ 数据前提

- 账本历史长度决定「同类胜率」是否有意义；新用户/新标的直接返回「样本不足」，**不许退化成全市场胜率混充同类**。
- 三层滤网需要明确的层定义；`docs/_archive/20261026_design/本土三层滤网_设计_20261016.md` 是权威源，实现前必须逐层对齐，未取到细节的部分写「未取到」，不得自造第四层。
- `-8%` 裁决：需产品/风控书面结论，本方案文档只登记冲突，不代为裁决。

### ⑤ 分阶段落地与验收线

- **P0（3 天）口径收敛**：抽出单一 `defense_line()`，三处硬编码改为引用，**行为零变化**（用现有单测 + 一次实盘影子对比证明距离输出完全一致）。**验收线：改动前后对同一批持仓输出的 `distance_pct` 逐位相同。**
- **P1（1 周）审计接口**：`/discipline/audit` 上线。**验收线：同类样本 <10 时返回「样本不足」；返回体必含 baseline 与 excluded 字段（缺字段即单测失败）。**
- **P2（1 周）前端抽屉 + 下单浮条**：**验收线：从点击「下单」到看到审计读数 <600ms；抽屉不遮挡 K 线主图；不含任何「建议买入/放弃」措辞（文案 lint）。**
- **P3（待裁决后）**：如裁决为「设默认 -8%」，才允许升级为硬拦截；否则永久停留在提示层。

### ⑥ 风险与不做项

- **不做**：不做「纪律分」排行榜、不做 AI 自动改单、不在裁决前做任何拦截。
- **风险**：审计若频繁报「违规」，用户会习惯性忽略（告警疲劳）。缓解：只在**命中层级 ≥2** 时弹抽屉，单层命中只在行内打点。
- **风险**：`similar_ops` 若用未来数据（如用了成交后才知道的市况标签），胜率会虚高。必须用**决策时点可见**的字段切片，实现时显式传 `as_of`。
- **Frozen**：`caliber.py`、`symbol_guard`、`number_audit`、交易 403、TQ 优先链、`SYSTEM_PROMPT` 一律不动；本方案需要触碰 `intraday_monitor.py` 常量替换，**标「需人工批准」**。

## 方案 3：09:05 双轨事件雷达 → 09:20 竞价异动自动印证 —— 事件强度 × 竞价抢筹匹配度共振得分 + 09:26 作战指令卡

### ① 跨模块化学反应

现状是「两条轨道各自跑，人脑做对齐」：

- **事件轨**：`catalyst_calendar.py` / `catalyst_screener.py` / `event_catalyst_engine.py` / `catalyst_windows.json` 产出当日事件与窗口；
- **竞价轨**：`auction_wudao_store.py`（`auction_wudao_daily` 多维因子）、`auction_pool.py`、`auction_tick_sampler.py`，`Auction.tsx` 展示；
- `Opportunities.tsx` 是机会页，`market_replay_daily`（Mig 222 盘后三池）是**事后**才知道今天谁真涨了。

三条轨道之间没有「印证」这一步。化学反应点是：**09:05 事件出现时不直接推票，等到 09:20 用竞价数据自动判定「这个故事有没有人真的掏钱」**，产出共振得分，09:26 给一张作战指令卡（不是推荐，是「今天这条线值不值得盯 + 盯什么价位 + 什么条件下放弃」）。

关键设计：**共振得分是二维的，不做成一维**。事件强度（0-100，来自事件本身：级别/新鲜度/涉及面）与竞价匹配度（0-100，来自竞价：高开幅度、竞价量比、抢筹集中度）分别显示，**只在右上象限（双高）才出指令卡**，其余组合只入观察池。一维得分会把「事件大但没人买」和「有人抢但没故事」压成同一个数，那是造假。

### ② 新增 UI 组件与按钮

- **`ResonanceQuadrant`**（新增，2×2 散点，非卡片）：X = 竞价匹配度，Y = 事件强度，点大小 = 涉及标的数，点颜色按红绿；对角线以上才高亮。`tabular-nums` 标注得分。悬停出浮条（`.shadow-float` 允许）。
- **`BattleCard`（作战指令卡，09:26）**：**这是全文档唯一一个允许"卡片"语义的对象**，因为它是「一次性、可丢弃、需要被截图」的产物。但即便它也用 hairline 而非重边框，内容固定四行：事件一行 / 共振两维 / 关键价位（失效位）一行 / 放弃条件一行。无「买入」字样。
- **`Auction.tsx` 顶部「今日印证」条**：一行横向列出 09:20 判定为「双高」的 3-5 条线，点击跳到对应 `BattleCard`。
- **按钮**：「重算印证」（手动触发，防自动任务失败后无路可走）。

### ③ 后端实现路径

1. 新模块 `src/core/resonance.py`：
   - `event_strength(events, as_of)` → 只读 `catalyst_*` 输出，权重表外置 JSON（可审）；
   - `auction_match(symbols, date)` → 读 `auction_wudao_daily` 已有因子，**不新增采集**；
   - `resonance(date)` → `{(symbol|theme): {event, auction, quadrant}}`，落 `resonance_daily`（新表，Mig 23x）。
2. 定时：09:05 事件快照（复用 `catalyst_windows.json` 窗口定义）、09:20 竞价印证、09:26 指令卡。**推送走 `notify_center.push_notification`（站内 + WS）+ `notifier.py` apprise 六类**——`PushDeer` 全仓 0 命中，**未落地，不得写进方案**。
3. 竞价数据可用性门禁：`auction_wudao_daily` 当日无数据时，`resonance` 返回 `degraded=true` + 原因，前端显示「竞价数据未到，仅事件轨」，**不许用昨日竞价填充**。
4. 归档：收盘后把 09:20 判定与 `market_replay_daily` 的真实结果 join，算「双高象限的当日命中率」，写入 `resonance_daily.result` 供长期校准。**这是让方案能自我否证的关键，不能省。**

### ④ 数据前提

- `auction_wudao_daily` 必须覆盖到 09:20 快照口径（不是收盘后回填口径）。**若现有落库是盘后回填，本方案的 09:20 判定就无法实现，必须先确认采集时点**——这是本方案的头号前置，未确认前只做盘后复盘版。

- 交易日历：非交易日不跑，避免空指令卡。

### ⑤ 分阶段落地与验收线

- **P0（3 天）时点核查**：确认 `auction_wudao_daily` 采集时点。**验收线：给出「字段 → 可得时点」表；若为盘后回填，则方案降级为「盘后印证」并明确写进 UI。**

### ⑥ 风险与不做项

- **不做**：不做「竞价异动选股」单轨推送（没有事件对照的竞价异动，噪音率极高）；不做大盘方向判断；不预测 09:30 后走势。
- **风险**：09:20-09:26 只有 6 分钟，链路任何一环慢就废。缓解：`/resonance/preview` 允许 09:15 预热计算，09:20 只做增量刷新。
- **风险**：事件强度权重是拍的。缓解：权重外置 + 每季度用归档数据回看各因子的分层命中率，**命中率无差异就删因子，不许留着凑数**。

## 方案 4：预测失误样本自动归因 → FactorIC 动态反馈 —— Miss 样本联合暗盘资金与因子衰减诊断归因

### ① 跨模块化学反应

`forecast_server.py:/referee/stats` 已经在做裁判（谁预测准），`factor_ic*.py` 家族已经在算因子 IC（`factor_ic`/`factor_ic_history`/`factor_eval`/`factor_ic_report`），`FactorIC.tsx` 是它们的界面。**但两边是各算各的**：裁判知道「kronos 昨天错了 3 个点」，FactorIC 知道「暗盘资金因子 IC 从 0.06 掉到 0.02」，没有任何东西把这两句话连起来。

化学反应点：**以 Miss 样本为索引，反查当时哪些因子在衰减、哪些资金流在背离**。具体做法——每次预测落库时冻结「当日因子快照」（哪几个因子贡献了什么权重），事后 Miss 时把该样本的因子贡献与全市场同日的因子 IC 变化做对照，自动产出归因条目：

- 「该样本 Miss 主因：暗盘资金因子方向相反（样本内贡献 -0.8σ），同日该因子全市场 IC 已降至 0.02（近 20 日分位 12%）」
- 「该样本 Miss 与因子无关：属跳空缺口，非模型可控」

**归因必须允许「不可归因」这个结论**，否则会强行给每个 Miss 编故事——这是本方案最重要的纪律。

### ② 新增 UI 组件与按钮

- **`MissAttributionList`**（新增，挂在 `FactorIC.tsx` 与 `Forecast.tsx` 共用区域，列表 + hairline 分隔，非卡片）：每行 = 一个 Miss 样本（日期 / 标的 / 预测值 / 实际 / 归因标签 / 置信）。
- **`FactorDecaySpark`**（新增，行内 40×14 微型折线）：该因子近 20 日 IC 走势，`tabular-nums` 不标刻度只标首尾值。
- **按钮**：「一键归因当日全部 Miss」（批量，异步任务 + 进度）、「导出归因 CSV」（给线下复盘）。
- **`FactorIC.tsx` 新增「归因」Tab**：与既有 IC 视图并列，不改既有布局。

### ③ 后端实现路径

1. 预测侧：`forecast_server.py` 的 `/predict` 落库时**必须同时落因子贡献快照**（现在是否落，未取到，需核；若无则新增表 `forecast_factor_snapshot`）。这是全方案的地基，**无快照则归因无从谈起**。
2. 归因侧：新模块 `src/core/miss_attribution.py`
   - `attribute(sample_id)` → 分四类：`factor_flip`（因子方向反）/ `factor_decay`（因子 IC 衰减）/ `gap`（跳空/一字）/ `unexplained`；
   - 复用 `factor_ic_history.py` 的历史 IC 序列，**不重算 IC**；
   - `bucket_stats()` → 每类归因的历史占比与后续修复率，供校准。
3. 反馈侧：归因结果**只写诊断表，不自动改模型权重**。`forecast_lib/model_weights.py` 的权重调整仍走既有回测闭环。**自动改权重是本方案的禁区**——归因是解释，不是训练信号。
4. API：`GET /forecast/miss/attribution?date=&model=`、`POST /forecast/miss/attribute`（异步）、`GET /forecast/miss/attribution/summary`。

### ④ 数据前提

- 因子快照需**预测时点**的因子值，事后补不了（会引入未来信息）。**必须在 `/predict` 链路里同步落库，越早越好。**
- 「暗盘资金」因子归属：L2 / TQ 口径，与主力意图、资金流不可换算，归因文案必须带「暗盘资金（L2）」标签。
- 归因需要的市况标签（跳空/一字）可从 K 线自算，无需外部源。

### ⑤ 分阶段落地与验收线

- **P0（3 天）快照落库**：`/predict` 增加因子快照写入。**验收线：连续 5 个交易日快照无缺；快照写入不使 `/predict` P95 增加 >100ms。**
- **P1（1 周）归因引擎**：`miss_attribution.py`。**验收线：`unexplained` 占比在首月 ≥30%（若 <10% 说明在编故事，需回查规则）。**
- **P2（1 周）界面**：`MissAttributionList` + `FactorDecaySpark`。**验收线：100 条记录渲染 <200ms；每条归因可点开看到原始因子贡献数值。**
- **P3（2 周）闭环校准**：按归因类别统计「后续同类 Miss 是否下降」。**验收线：给出 3 个月对比表；若无改善，明确写「归因未产生决策价值」并停止扩展。**

### ⑥ 风险与不做项

- **不做**：不自动改模型权重；不把归因当「模型解释」对外宣传；不对单个 Miss 做「必然原因」断言（只给类别 + 置信）。
- **风险**：归因规则写多了会变成「凡是 Miss 都能解释」的安慰机器。缓解：强制保留 `unexplained` 类并**在 UI 首位显示其占比**。
- **风险**：`forecast_server.py` 是高并发敏感路径（`_predict_semaphore` 限 2 并发），快照写入必须**异步旁路**，不得阻塞推理。

## 方案 5：通达信公式双向编译器 —— 自然语言 ↔ 指标公式，对齐口径矩阵并前端渲染 + 回测胜率

### ① 跨模块化学反应

`docs/tq-formulas/` **已确认存在**，现有 6 个公式文本（`1_AI机构活跃度.txt`、`2_趋势操盘线.txt`、`3_牛熊线.txt`、`4_暗盘资金.txt`、`5_GS波段.txt`、`6_涨停强度选股.txt`）+ `README.md`。`src/collectors/tq_formula_signals.py` 已能把条件选股公式跑成 `tq_formula_signal_daily` 日序列（`formula_scan`，108 个公式中挑了三类做市场宽度），`backtest_lab` 已能对信号做前瞻胜率。

所以「公式 → 信号 → 胜率」这条链**已经通了**。缺的是两头：

- **头（自然语言 → 公式）**：想把「回踩 20 日线不破 + 缩量」变成可跑的公式，今天只能手写；
- **尾（公式 → 人话 + 前端渲染）**：公式文件是纯文本，`StockWorkbench` 看不到它当前是「触发/未触发」，`caliber.py` 的口径矩阵也没和公式语义对齐（比如公式里的「资金」到底是 eastmoney4 还是 L2）。

化学反应点：**双向 + 口径对齐**。单向翻译器会产生「看着对但口径错」的公式，这比不翻译更危险。因此本方案的**核心不是 LLM，是口径矩阵**：每个公式必须声明它引用的数据口径（四档结构 / 资金流 / 主力意图 / L2 / 纯价量），未声明的公式**不允许进入回测**。

### ② 新增 UI 组件与按钮

- **`FormulaWorkbench`**（新增页面区，挂在 `StockWorkbench` 第三栏可折叠区，或独立 `Formula` 页；具体挂载点建议独立页，避免个股页拥挤）：左 = 自然语言输入框 + 生成的公式文本（等宽字体 12，`tabular-nums`），右 = 该公式的**回测胜率三联**（样本数 / 同池基准 / 剔除一字板标记）。
- **`CaliberBadge`**（新增，沿用既有口径标签视觉）：公式旁标 `纯价量` / `tdx_exday4` / `eastmoney4` / `tick` / `L2(TQ)`，**多口径公式显示多个 badge 且不可合并**。
- **K 线图打点**：`KlineChart.tsx` 主图叠加公式触发点（小三角，买红卖绿），由 `KlineSubchart` 第 8 档显示公式值曲线。
- **按钮**：「编译」（NL→公式）、「反编译」（公式→人话）、「用该公式回测」、「保存到公式库」。保存按钮需二次确认并强制填口径。

### ③ 后端实现路径

1. 新模块 `src/core/formula_compiler.py`：
   - `nl_to_formula(text)`：LLM 出公式 + **强制结构化输出（含 `caliber: list[str]` 与 `assumptions`）**，未给 caliber 直接判失败；
   - `formula_to_nl(code)`：解析 + 生成说明，同样要求回填 caliber；
   - `validate(code)`：语法/函数白名单校验（只允许通达信官方函数，禁用未定义变量），**不允许直接执行任意代码**。
2. 回测：走 `tq_formula_signals.fetch_formula_signals` 同路径（条件选股），或对本地 K 线用 `backtest_lab.evaluate_bars_universe` 等价重算，**两条路径必须给出同一口径的胜率三联**，差异需解释。
3. 存储：新表 `formula_library`（公式文本 + caliber + 创建人 + 版本），公式文件同步写 `docs/tq-formulas/`（**该目录已存在，新增文件按 `7_xxx.txt` 续号**）。
4. 安全：LLM 生成物一律不落盘为可执行文件，只存文本；`formula_process_mul_xg` 调用沿用既有网关，**不新增直连**。

### ④ 数据前提

- 通达信客户端 `formula_get_all(1)` 已有 108 个条件选股公式（源码注释实测），acCode 必须**从客户端实测取，禁止手写猜**（`tq_formula_signals.py:53` 已明确此纪律）。
- 口径矩阵：需以 `caliber.py`（Frozen，只读引用）为权威，**不改它**；公式的 caliber 声明只能是它的子集枚举。
- 跨口径公式（同时用资金流 + 价量）在回测时必须分口径给胜率，不能合成一个数。

### ⑤ 分阶段落地与验收线

- **P0（3 天）公式库盘点**：把现有 6 个公式逐个补 caliber 声明并回测。**验收线：6/6 公式有 caliber；每个公式有胜率三联（样本 <30 的标「样本不足」）。**
- **P1（1 周）校验与编译**：`validate()` + `nl_to_formula()` 只做只读建议（不自动保存）。**验收线：对 20 条自然语言描述，生成公式可编译率 ≥70%；caliber 缺失率 0（强制）。**
- **P2（1 周）前端 + 打点**：**验收线：公式触发点在 K 线上与 `tq_formula_signal_daily` 日序列逐日对齐（对拍 3 个公式 × 60 日，0 差异）。**
- **P3（1 周）反编译 + 库管理**：**验收线：反编译文本经人工抽检 10 条，语义错误 ≤1 条。**

### ⑥ 风险与不做项

- **不做**：不做「AI 自动生成选股公式并直接推送」；不做公式自动交易；不允许公式绕过 `symbol_guard` / 交易 403 / TQ 优先链（均为 Frozen）。
- **风险**：LLM 会生成「语法正确但语义错」的公式（如 `REF(C,1)` 与 `REF(C,1)*1.0` 之外的隐式未来函数）。缓解：白名单 + 禁 `ZIG`/`PEAK` 类未来函数 + 回测强制前瞻对齐检查。
- **风险**：胜率三联若不同屏，用户会只看胜率数字。缓解：UI 层把基准与剔除标记做成**不可折叠**，胜率数字本身字号不高于基准。
- **需人工批准**：`docs/tq-formulas/` 新增公式文件属于共享资产，写入前需 owner 确认编号规则。

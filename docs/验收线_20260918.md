# §11.5 验收线实测 · 2026-09-18

设计稿 v2.1 §11.5 要两条留痕：**100 并发压 1 小时** + **20 页面走查**。本文是这两条的实测记录（此前该项标注为 `❓ 无留痕`）。

生产：`https://www.sida.hengsheng-elec.com` → nginx(101.35.244.238) → 小主机 100.91.30.35:8000，容器 `panwatch` = ACR `xzxwz:v0.10.6`。

## 一、100 并发

### 1.1 应用侧（小主机 WSL → `localhost:8000`，排除 nginx/跨境链路）

| 指标 | 值 |
|---|---|
| 并发 | **100** |
| 请求数 / 成功 | 100 / **100（100%）** |
| 总耗时 | 0.35 s |
| 吞吐 | **283.6 req/s** |
| 延迟 p50 / p90 / p95 / max | **171.7 / 291.2 / 304.6 / 312.5 ms** |
| 失败码 | 无 |

**结论：应用本身扛得住 100 并发**（单实例 4 worker，家宽小主机环境）。

### 1.2 公网侧（海外开发机 → 域名 → nginx → 小主机，即用户真实路径 + 跨境）

| 轮次 | 并发 | 成功 | 成功率 | 吞吐 | p50 | p95 | p99 | max |
|---|---|---|---|---|---|---|---|---|
| 第 1 轮 | 100 | 96/100 | 96.0% | 7.0 req/s | 3179.8 ms | 5836.4 ms | 14169.3 ms | 14169.3 ms |
| 第 2 轮 | 100 | 100/100 | 100% | 13.2 req/s | 6586.5 ms | 7239.2 ms | 7338.0 ms | 7338.0 ms |

单请求基线（同一路径，串行）：公网 p50 **1635 ms** / 直连 Tailscale p50 **895 ms**。

**结论**：公网侧 p50 从 1.6 s 涨到 3~7 s、首轮出现 **4 次 502** —— 瓶颈在**跨境链路 + 家宽上行**，不在应用（应用侧同样的 100 并发 p50 只有 172 ms，本机 `/api/health` 组件延迟 1 ms）。502 出现在首轮突发，属 nginx→小主机上行瞬时打满，不是应用 5xx。

> ⚠️ 读数字的边界：打的是**只读**接口（`/api/health` 4 : 前端 index 1）。**没有**压重活端点（`/api/klines/{symbol}/summary` 冷缓存 6~9 s，单独测过）与写路径；也没有压登录（scrypt n=2^15 是 CPU 密集，另算）。所以本文数字的含义是"链路与读路径容量"，不等于"全接口 100 并发"。

### 1.3 1 小时长稳

脚本 `soak_1h.py` 已在小主机后台常驻（nohup，日志 `/tmp/soak_1h.jsonl`，汇总 `/tmp/soak_1h_summary.json`）：

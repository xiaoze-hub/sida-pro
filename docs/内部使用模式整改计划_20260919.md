## 一、决策背景（2026-09-19 用户拍板）

| 项 | 决定 |
|---|---|
| 产品定位 | **暂时内部使用**，不对外商业化、不开放推广 |
| 注册入口 | **改为邀请码注册**（管理员生成邀请码，可控放人） |
| 合规面收尾 | 与邀请码同批做（本文 Phase 2–4） |

**合规依据（判定"内部使用 + 不收费"是当前最低风险姿态）**：
- 证监会公告〔2012〕40号《关于加强对利用"荐股软件"从事证券投资咨询业务监管的暂行规定》——
  向投资者**销售或提供**"荐股软件"并**直接或间接获取经济利益**的，属于从事证券投资咨询业务，须证监会许可。
- 《关于规范面向公众开展的证券投资咨询业务行为若干问题的通知》——任何机构或个人**向公众**以电脑网络等形式
  提供证券走势分析、预测或建议，须先行取得资格（**不以收费为要件**）。
  → **真正的红线是"面向公众"三个字**，所以公开可注册的入口必须收掉。
- 《生成式人工智能服务管理暂行办法》第十七条——调用**已备案**大模型 API 面向境内公众服务的，**只需登记**。
- 刑事边界（刑法225条非法经营罪，判例：京圈富少案 2年6个月+罚金1500万；陆某案 5年6个月+罚金250万）——
  打击的是**以营利为目的 + 长期性**的经营行为。

**结论**：内部使用 + 不收费 + 不面向公众 = 三个安全支点。本计划就是把"不面向公众"落到代码里。

## 二、Phase 1：邀请码注册（P0，责任方：Hermes；验收线见下）

### 1.1 数据模型（迁移 v177）
```
invite_codes
  code         TEXT PK          -- 8 位 base32（去掉 0/O/1/I 等易混字符）
  note         TEXT            -- 备注（给谁用的，便于回收）
  max_uses     INT  DEFAULT 1  -- 可用次数
  used_count   INT  DEFAULT 0
  expires_at   DATETIME NULL   -- 过期时间（NULL=不过期）
  disabled     BOOL DEFAULT 0  -- 管理员作废
  created_by   TEXT            -- 生成者
  created_at   DATETIME

invite_code_uses（审计，不可省）
  code, user_id, username, client_ip, used_at
```

### 1.2 核心逻辑 `src/core/invite_codes.py`
- `generate_code()` / `create(...)` / `list_all()` / `disable(code)` / `redeem(code, user)` **事务内**：
  `UPDATE invite_codes SET used_count=used_count+1 WHERE code=? AND disabled=0 AND used_count<max_uses AND (expires_at IS NULL OR expires_at>now)`
  → 受影响行数=0 即拒绝（**防并发超发**，不能用"先查后改"）。
- 失败原因要**分清**：不存在 / 已作废 / 已用尽 / 已过期 —— 各自给明确文案（别一律"邀请码无效"）。

### 1.3 接口
| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/admin/invite-codes` | owner | 生成（可带 note/max_uses/expires_at） |
| GET | `/api/admin/invite-codes` | owner | 列表（含已用次数） |
| POST | `/api/admin/invite-codes/{code}/disable` | owner | 作废 |
| POST | `/api/auth/register` | 公开 | **新增必填 `invite_code`**（当 `REGISTER_MODE=invite`） |

### 1.4 运行模式开关
`REGISTER_MODE = invite | open | closed`（**默认 invite**；`open` 保留现有行为便于自测；`closed` 直接关闭注册）
- `invite`：必须有有效邀请码
- `open`：等同今天的行为（仅在明确需要时临时开）
- `closed`：注册一律 403

### 1.5 前端
- `/login?mode=register`：加**邀请码**输入框（放在邮箱之前，先验码再发验证码更省邮件额度）；
- 页面顶部按模式显示：`invite` → "内测邀请制，请使用管理员发放的邀请码"；`closed` → "当前不开放注册"并隐藏表单；
- 落地页/档位页 CTA 按模式调整（不出现"立即注册"字样）；
- Admin 页新增「邀请码」区块：生成 / 复制 / 查看已用次数 / 作废。

### 1.6 验收线（**每条都要有可跑的测试或生产实证**）
1. 无邀请码 / 错误码 / 已作废 / 已用尽 / 已过期 → 注册被拒，且**文案各自可区分**；
2. 一个 `max_uses=1` 的码用两次 → 第二次失败；`max_uses=3` 用满 3 次后失败（**并发下不超发**：并发测试）；
3. 邀请码使用**落审计表**（who / when / ip）；
4. 生成/列表/作废端点**仅 owner**（普通用户 403）；
5. **公开面不泄露邀请码**：匿名访问 `/developers`、`/tiers`、`/login` 页面文本里**不得出现**任何邀请码字符；
6. 邀请码**不出现在日志明文**（日志只留后 4 位或 hash）；
7. 前端钉子：`register` 请求体必须带 `invite_code` 字段（源码级断言 + 真实请求断言）。

## 四、Phase 3：备案号与隐私政策（P1）
1. **页脚补 ICP 备案号**（当前全站**没有展示**，这是国内站点的硬要求）——需要你提供：备案主体名称 + 备案号（如 粤ICP备XXXXXXX号-N）。
2. 隐私政策补 4 项：**第三方共享清单 / AI 处理说明（数据会送给哪些模型、是否出境）/ 保存期限 / 未成年人条款**。
3. 确认 AI 端点**全部为境内**（BYOK 模式下在设置页对 base_url 做境内白名单校验；
   若必须允许境外端点，则在隐私政策中显式告知 + 单独同意）。

## 一、P0（v0.10.25 ~ v0.10.27）：终端主角度 + 字阶 + 缺数

**P0 的存在理由**：铁律里唯一带数字的一条（K 线 ≥80% 屏宽）当前**被违反**（个股页 0.552），
且首页字号 13 种、个股页 73 处平铺 `--` —— 这三项直接决定"像不像专业终端"。

### P0-1 个股/指数页：把 K 线做成主角（0.552 → ≥0.80）

**实测解剖（1600×900，生产）**

```
视口 1600 | 侧栏 240（但已支持折叠 w-16=64）| 右栏 320（固定）| K线 canvas 884 → 0.552
canvas 左偏移 277 = 侧栏240 + 容器居中/内边距 37
图内右侧价格轴占 ~62px（不可省）
```

**四步改法（按性价比排序）**

| # | 改动 | 增益 | 风险 |
|---|---|---|---|
| 1 | 右栏 320 → **可折叠图标条 56**，个股页**默认折叠** | +264px | 低（本页内） |
| 2 | 工作台页**默认折叠全局侧栏**（localStorage 已有键，仅改默认值判定） | +176px | 中（全站默认值，需回归其它页） |
| 3 | 工作台容器 `max-w-[1500px]` → `max-w-none`（其余页不动） | +74px | 低 |
| 4 | 图内读数/图例**改 overlay**，不再占列宽 | 视觉收益 | 低 |

预计：884 + 264 + 176 + 74 ≈ **1398 → 0.874**（≥0.80 有余量）
**验收**：巡检 `个股页 klineShare ≥ 0.80` 且 `指数页 ≥ 0.80`；展开侧栏/右栏时按用户显式选择，**不算越线**（口径写进脚本注释）。
**依赖**：无。**改动面**：`frontend/src/pages/StockWorkbench.tsx`、`workbench/IndexBody.tsx`、`App.tsx`（默认值判定）。

### P0-2 首页：字号 11→≤6 + 首屏"结论行"

- **改动面**：`frontend/src/pages/Dashboard*.tsx`（含 `DashboardCustomizer` 默认项）。

### P0-3 `<MissingFields/>` 缺数折叠（个股页 73 → ≤12）

### P1 的前置假设有两处是错的(2026-09-18 复核)

| 文档页"单栏 7281px、**无目录**" | **错**: `DevPageLayout` 早有 **sticky 左目录**(8 章锚点, `md:sticky`)。真实缺口只有"调试台非常驻" + "无档位定价对比" |

**结论**: 我的两处判断都是"**用度量推断功能缺失**"(页高长 → 以为无目录; 列表没看到"结论"字样 → 以为没结论行)。
DOM 探针能量"多长/多密/多少种字号", **量不出"有没有某功能"** —— 后者必须看代码或交互。已写进设计稿"方法论教训"。

### 测量基准(2026-09-18 教训, 重要)

`dash` / `zeroish` 是**数据状态依赖**指标: 同一天 **18:50** 测个股页 `dash=46`(部分数据源未补齐),
**19:30** 复测 **0**(数据回流完成)。即: 不加时点约束地比这两个数, 会把"数据没回来"误读成"代码改坏了"。
- **结构指标**(随时可比): `klineShare` / `hairline` / `cards` / `fontCount`;
- **数据指标**(须固定时点, 建议盘后 16:00 之后 + 记录源状态): `dash` / `zeroish` / `density`。
- 已写进 `scripts/terminal_audit.py` 文档头, 后续回填一律注明测量时点。

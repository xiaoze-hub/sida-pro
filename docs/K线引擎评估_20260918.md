## 一、结论先行

**建议：合并到 `KlineChart`（KC）为唯一内核，`InteractiveKline`（IK）与 `MinuteLwcChart` 最终退役；
但分阶段做，第一步只做"类型收口 + 能力补齐 + 迁移 1 页"，用视觉/DOM 走查对齐后再逐页推进。**

- 不是"二选一砍掉一个"（那是优胜劣汰），也不是"两边功能都往一处堆"（那是盲目合并）：
  KC 做**内核**，IK 的独有能力（分时模式 / 主力意图结构 / 分层开关）作为**可选模块**并入 KC。
- 逆向（以 IK 为内核）不推荐，理由见 §四。

## 四、为什么是"KC 内核 + IK 能力并入"，而不是反向或双引擎并存

1. **主干已经是 KC**：旗舰页 `StockWorkbench`（六图层 / §10.2 交互 / §12 数据源裁决 / §6.2 成交标记）、
   `ShadowAccount`、`RangeStatsCard` 全在 KC 侧；近两周新增能力（tradeMarkers、sourceReady、costLines、
   subchart、range stats、crosshair）**全部长在 KC 上**。
2. **IK 的"独有"其实是可移植功能，不是内核差异**：分时模式 = `MinuteLwcChart` 的封装；
   主力意图结构 = 一个数据形状的渲染层；分层开关 = props 形状差异。三者都不需要另一套图表引导。
3. **双引擎的代价是实测过的**：本轮 B1 把图表库从 CDN 改成打包自托管时，**两个文件都得改**
   （`getLW()` 各一份）；任何全局能力（数据源裁决、成交标记、图表库升级）都要改两遍。
   再加类型重复：`GsSignalPoint`、`FundFlowBar`、`KlineEvent` 在两个文件里各定义一次。
4. **不推荐反向（IK 为内核）**：等于把 §6.2/§12/range-stats/subchart 四个已上线并带测试的能力
   往 IK 搬 —— 回归面更大、收益更小。
5. **不推荐长期双引擎并存**：边界会持续漂移（新能力总得选一边），最终仍是上面第 3 条的成本。

## 五、实施计划（分四步，每步都有验收线）

| 步 | 内容 | 验收 |
|---|---|---|
| **P0 类型收口** | 新建 `packages/biz-ui/src/lib/kline-types.ts`，收敛 `GsSignalPoint`/`FundFlowBar`/`KlineEvent`/`MainIntentStructured`/`SupportPressureLine` 等重复类型；IK/KC 从该文件 re-export（**保持对外签名不变**，旧 import 路径照旧可用） | tsc 0 / vitest 全绿；`git grep` 显示类型定义只剩 1 处 |
| **P1 能力补齐到 KC** | ① `mode: 'kline'\|'minute'`（内部复用 MinuteLwcChart）；② `mainIntent` 呈现层；③ `LayerState` 结构化开关（兼容现有 `layersVisible`） | 每项配单测；KC 现有 4 个测试文件不回归 |
| **P2 逐页迁移** | 顺序：`IndexBody`（指数页，无成交标记/成本线，风险最低）→ `PaperTrading` → `AnalysisDetail` → `KlineModal` | 每页迁移后：走查脚本（`/tmp/ui_sweep.py`）同一路由 **before/after 截图 + DOM 探针对齐**，无新增「无数据/`--`」、无横向溢出；tsc/eslint/vitest/build 全绿 |
| **P3 退役** | 删除 `InteractiveKline.tsx`（`MinuteLwcChart` 转为 KC 内部私有组件或一并收进 `lib/`），并把 `biz-ui/index.ts` 导出收敛 | 新增 ui-rules 规则：**全仓只允许一个 `createChart` 引导模块**（`KlineChart`），违者 CI 红 |

**工作量口径（可核对，非拍脑袋）**：3 组件 2825 行 / 6 个引导点 / 4 个消费页面 + 1 个模态 /
类型被 6 处引用。P0+P1 是纯增量（不动消费方），P2 每页可独立回滚（一页一个 commit）。

## 六、不做什么（明确划界）

- **不做** UI 视觉重设计（与本评估无关；视觉问题走 `docs/UI走查_20260918.md` 的 B1–B4 批次）。
- **不新建第三套引擎**。
- **不在没有页面级视觉/DOM 比对的情况下删旧组件** —— 迁移一页、验证一页、再删一页。
- **不为了统一而改 props 语义**：P0 保持对外签名兼容，避免把"重构"变成"破坏性改动"。

## 七、风险与前置

| 风险 | 处置 |
|---|---|
| 分时模式在 KC 里行为不等价（昨收基准/波段/故障语义 KJ-042「空列表是故障不是停牌」） | P1 先把这三条行为写成测试（含"空列表=故障"），再迁移页面 |
| `KlineModal` 依赖 IK 的默认尺寸/紧凑布局 | 迁移前先截图存档，迁移后逐项比对 |
| 类型收口引发大范围 import 改动 | P0 只 re-export，不改调用方；`git grep` 验证类型定义唯一性 |
| 迁移期间两套代码并存导致改两遍 | P2 期间冻结"非迁移必要"的图表改动（新需求先进 KC） |
